# Longform Scenario Review

長編アドベンチャーを、**作る側とは別の目**で壊しにかかるレビュー用スキル。作成は `ink-scenario-creator`、本スキルは指摘と検証を担当する。修正は明示依頼がある場合だけ行う。

同一生成パスでの自己採点は確証バイアスに弱い。作者の封印知識で因果を補わず、初見プレイヤーが実際に情報を得る順序、実際のコマンド、実際の変数条件、実際の資源収支から検査する。

## 1. 最初に適用パックを宣言する

レビュー開始時に主構造・副構造を特定し、次の表を埋める。Applicable / N/A を理由なしで省略しない。

| パック | Applicable / N/A | 適用条件 | 必読 |
|---|---|---|---|
| **Common Comprehension** | 原則 Applicable | すべての長編 | [common_comprehension_review.md](./references/common_comprehension_review.md) |
| **Fixed Command Harness** | 謎・探索操作・RPG操作があれば Applicable | 世界への働きかけを固定コマンドで実演する作品 | [fixed_command_harness_review.md](./references/fixed_command_harness_review.md) |
| **RPG Economy** | RPGが主構造または主要副構造なら Applicable | HP・消耗品・装備・戦闘・資源管理を主要判断として約束 | [rpg_economy_review.md](./references/rpg_economy_review.md) |
| **Mystery Craft** | 隠蔽・推理・反転が中心なら Applicable | 推理ミステリー、長編の真相開示 | [longform_mystery_craft.md](../ink-scenario-creator/references/longform_mystery_craft.md)、[puzzle_design.md](../ink-scenario-creator/references/puzzle_design.md) |
| **Ink / MCP** | 実行可能なInkなら Applicable | `engine/assets` またはコンパイル対象 | [adventure_mcp_patterns.md](../ink-scenario-creator/references/adventure_mcp_patterns.md) |

### N/Aにしてはいけない例

- RPGを名乗るが回復が不要：RPG EconomyのFAILでありN/Aではない。
- 推理を名乗るが答えN択だけ：Fixed Command Harness / Mystery CraftのFAILでありN/Aではない。
- `public_status` がない：Ink / MCPのFAILであり、本文に手動表示があることは代替にならない。

## 2. 参照規則の優先順位

矛盾時は次を優先する。

1. エンジン・Adventure MCPの制約
2. 適用ジャンルパックの非交渉要件
3. 作品で合意・宣言された約束
4. 一般的なジャンルガイド
5. 文体・好み

一般的なジャンル慣習からコマンドや数値則を創作しない。固定コマンドは、`PUZZLE_DESIGN.md` §6 のジャンル別パレット、`ink-scenario-creator`、適用ジャンルパックに書かれた語彙だけを根拠にする。推理へ冒険パレットを、脱出へRPG用対応を流用しない。

## 3. レビュー手順

### Step 1: 対象と変更範囲を確定する

- 対象 `.ink`、生成 `.json`、関連テスト、設計資料を列挙する。
- コミット指定がある場合、対象ファイルが本当にそのコミットに含まれるか確認する。
- untrackedファイルは「指定コミットの変更」と混同しない。
- 既存仕様と変更差分を分け、今回の回帰か以前からの欠陥かを示す。

### Step 2: 初見順で素読みする

- 封印層・真相を知る前のプレイヤー順で読む。
- 各章・階層で「自分は今何を理解し、次に何をすると思うか」を記録する。
- 初見の予想結末を一度言語化し、意図した反転・ドラマチックアイロニー・既視感と比較する。
- 作者だけが知るフラグや後の説明で、現在の理解不足を正当化しない。

### Step 3: Common Comprehensionを実施する

[common_comprehension_review.md](./references/common_comprehension_review.md) に従い、最低限次を確認する。

- 情報を「謎の対象／解法／背景前提／操作・資源規則」に分類したか。
- 開幕で誰・目的・完了条件が分かるか。
- 各遷移が「目的→観測結果→形成できる認識→次の行動理由」でつながるか。
- 重要な事実に観察・証言・既知能力・推論等の出所があるか。
- 不可逆・高コスト・一度きりの選択前に、コスト種類と不可逆性が読めるか。
- 本文が説明するエンディング条件と実際のInkゲートが一致するか。
- 中心設定が起源から各結末まで一つの因果モデルを作るか。

### Step 4: Fixed Command Harnessを実施する

Applicableなら [fixed_command_harness_review.md](./references/fixed_command_harness_review.md) を全項目実施する。

必須成果物：

1. 作品の操作形式に合うジャンル別パレット（探偵・推理／脱出／冒険）の選択と根拠
2. 場所ごとのトップレベル動詞表
3. 選択した固定パレットとの差分
4. 主要解法ごとの outcome-gating 表
5. N択が「解決過程」か「最後の確認」かの分類
6. 選択したジャンルのPoCとの構造比較（推理は `detective_command.ink`、脱出は `escape_room.ink`、冒険・RPGは `adventure_command.ink` / `legendary_forge_cmd.ink`）
7. 推理では `つきつける→人物→証拠`、RPGでは適用ジャンルパックの正規コマンド対応との照合

主構造の謎・RPGが、選択すべきジャンル別パレットを使わず、独自トグルUI、答えN択、知識フラグ後に湧く解決専用コマンドで進む場合はBlocker候補とする。

### Step 5: RPG Economyを数値検算する

Applicableなら [rpg_economy_review.md](./references/rpg_economy_review.md) を使い、感想でなく数値を出す。

最低限：

- 主資源
- 開始値
- 正解装備・ノーミスの必須通行料
- 携行回復量と入手数
- 余剰マージン
- ノーミス／初見／ごり押し／リスク購入の階層別時刻表
- 資源ごとの固有役割
- 供給の前積み
- リスク選択・リスク購入の期待収支
- 必須アイテム・ヒントの取得階と使用階の距離

必須条件は `通行料 > 開始主資源`。ノーミス経路で回復不要、無料のクラス解答で全損耗を回避、決戦直前に全回復、といった状態はRPG経済の不成立として独立報告する。固定コマンド違反を直しても数値バランスが自動的に直るとは扱わない。

### Step 6: Mystery Craftを実施する

Applicableなら [longform_mystery_craft.md](../ink-scenario-creator/references/longform_mystery_craft.md) と [puzzle_design.md](../ink-scenario-creator/references/puzzle_design.md) を照合する。

- **視点契約**：地の文・主人公の観察・無口主人公等、宣言した視点形式が一貫するか。内面描写を一律必須にしない。
- **NG結果**：GMやクイズ司会の採点でなく、人物・物理・制度の反応で返すか。
- **章の因果**：章の目的と得た情報が次章を動かすか。
- **フラグ**：結末を意味的に変えるか。必須進行と任意真ED鍵を分離するか。
- **伏線の重複無効化**：任意setupの知識を、別の必須経路で全員へ再配布していないか。
- **回収**：重複回避を口実に章を孤立させていないか。
- **ネタばらし**：固有名・結論・真相・深い内部状態を早出ししないか。
- **手続き×立場**：手続き前の断定、有能な手続きが見落とす後出し、権限外知識がないか。
- **配分**：中核を早く解きすぎないか。手がかり強度が意図したペースに合うか。
- **推理の質**：再認N択、一本道○×、法則の恣意性、難読表現で偽装した難易度になっていないか。
- **予測可能性**：二重の意味ではなく、表面から真相を直接言い当てられる伏線になっていないか。
- **制約**：人物・道具・装置が確立済み能力を超えて万能化していないか。

### Step 7: 選択肢の消失を分類する

「選んだ選択肢が消える」ことを一律違反にしない。

- 再選択を原則残す：移動、観察、状態確認、繰り返せる会話、ナビゲーション。
- 消えてよい：一度きりの取得、破壊、消費、支払い、明示された不可逆決断、世界状態の変化で成立しなくなった行為。

普通の調査に見える選択が他の調査や真ED鍵を無警告で永久消失させる場合は、選択保持と意思決定可能性の両方で指摘する。

### Step 8: Ink / MCPを検証する

機械検証は、実行したものごとに次で報告する。

- `PASS`
- `FAIL`
- `MISSING`
- `NOT RUN`

必須検証表：

| 検証 | 状態 | コマンド・テストパス | 証拠・失敗内容 |
|---|---|---|---|
| Inkコンパイル | | | |
| spoiler lint | | | |
| シナリオ固有の成功経路 | | | |
| 通常失敗・回復 | | | |
| 全EDまたはEDクラス | | | |
| 不可逆選択・資源枯渇 | | | |
| 固定コマンド挙動 | | | |
| MCP `scene` / `choices` / `input` | | | |
| MCP `status` / `public_status` | | | |

ルール：

- コンパイル成功は到達性・収支・エンディング条件の証明ではない。
- テストが存在しない場合は `MISSING`。テストが走っていないのに「緑」と書かない。
- `public_status` は必ず宣言する。HP・消耗品・公開装備・状態・現在地など必要な公開状態を含め、解法・真相・勝敗・正解値・隠しアイテムを含めない。
- 本文中の手動ステータス表示はMCP `status` の代替ではない。
- RPGでは、必須装備なし／あり、回復使用、ごり押し敗北、資源枯渇後ED、代表数値を確認する。

### Step 9: 機械結果を本文と照合する

静的lint・コンパイル・自動探索の結果は候補または限定的証拠であり、人間レビューの代替ではない。

- linterが対象語を検出しないだけで、意味上のネタばらしがないとは限らない。
- 到達できた一本だけで、他の順序・クラス・資源状態・EDが正しいとは限らない。
- フラグ名ではなく、実際の選択肢条件と経路を確認する。

## 4. 重大度

- **Blocker**：主構造のハーネス不採用、到達不能、重大ソフトロック、虚偽のエンディング契約、必須MCP状態欠落、真相と操作規則の根本矛盾。
- **Major**：重要な因果・コストを理解できない、RPG経済不成立、無警告の不可逆ロックアウト、中心因果モデルの矛盾、前出し／後出し。
- **Moderate**：認知操作の反復、伏線の重複無効化、局所的なペース・供給・余剰マージンの問題。
- **Minor**：用語、語り口、局所的な明瞭性。

点数でハードゲート違反を相殺しない。Blockerが一つあれば、総合点が高くても承認扱いにしない。

## 5. 指摘の必須形式

各指摘を次の順で書く。

```text
[重大度] 短い要約

場所・引用:
  file:line と該当本文

再現経路:
  具体的なプレイヤー入力、状態、取得情報、選択順

期待される契約:
  リポジトリ上の規則と参照箇所

実際の結果:
  現在の誤動作・誤理解・数値

プレイヤーへの影響:
  なぜ理解不能、不公平、形骸化、または到達不能になるか

根本原因:
  情報分類、固定コマンド、フラグ、因果モデル、資源収支等

修正方向:
  謎の答えを明かさず、どの構造を直すべきか
```

憶測だけの指摘を出さない。抽象的な「説明不足」「バランスが悪い」ではなく、入力状態から誤結果へ至る具体例を示す。

## 6. 出力順

1. 対象・変更範囲・適用パック
2. Blocker
3. Major
4. Moderate
5. Minor
6. 構造別スコアカード（理解、コマンド、RPG経済、推理、状態、テスト）
7. 検証表（PASS / FAIL / MISSING / NOT RUN）
8. 良くなった点・保持すべき点
9. 人間が最終確認すべき点 1〜3件

問題だけでなく、説明追加が正しく「前提」を明確化している改善、因果を強めた変更、保持すべき成功も短く記録する。

## 7. 校正用の既知失敗セット

次はファイル名専用のハードコード規則ではなく、レビューが本質的欠陥を拾えるか確認する校正例。

### hoshigui_no_kane_expanded 型

- 祠・振り子・ボスが固定コマンド＋outcome-gatingでなく、完成済み解法N択・解決専用コマンドになっている。
- 最適経路でHP満タン・回復未使用のままボスを倒せ、必須通行料が実質0である。
- `public_status` がなく、MCPからRPG状態を取得できない。
- 普通の宿屋調査一回が、無警告で歌と真EDを永久に失わせる。
- 三つの儀式要素で十分と説明しながら、未説明の信頼度を第四条件にする。
- 起源、例外的知覚、共同儀式の代替、破壊結果が一つの因果モデルになっていない。

### star_marrow_mine 244f831 型

- 恒久強化の代償警告を観察しなくても購入できる回帰。
- 危険を観察しなくても高コスト経路を選べる回帰。
- 大幅な状態機械変更に対するシナリオ固有スモークテストがない。
- 連続階層で同じ荷重・支持構造の認知操作を反復する。

## 8. 独立性と修正境界

大規模レビューでは、因果、理解、固定コマンド、RPG経済、推理、Ink/MCPを別観点で並行調査してよい。各観点は同じ指摘形式と参照規則を使い、最後に重複を統合する。

本スキルの既定成果物はレビュー指摘である。本文、数値、フラグ、テストの修正はユーザーが明示的に依頼した場合だけ行う。
