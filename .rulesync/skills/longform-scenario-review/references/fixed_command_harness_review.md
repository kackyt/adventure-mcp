# Fixed Command Harness Review

謎・探索・RPG上の障害を、リポジトリで定義された**固定コマンドパレット＋outcome-gating**で実演させているかを検査する。

一般的なRPGの慣習からコマンドを推測・創作してはならない。対象作品が採用するパレットと、次のリポジトリ契約だけを根拠にする。

## 2. 最優先原則

謎は「答えを選ぶゲーム」にしない。プレイヤーは、世界を調べ、対象へ働きかけ、結果を観測して解を実演する。

```text
固定された動詞
→ 場所・状態に応じた対象
→ 必要なら道具と対象
→ 内部状態によって変化する outcome
```

正解を知った後にだけ解決専用コマンドを湧かせない。コマンドの出現自体をメタな答えにしない。

## 3. ジャンル別パレットを選ぶ

レビュー開始時に、作品の主たる操作形式に対応するパレットを [PUZZLE_DESIGN.md §6](../../../../docs/06-reference/PUZZLE_DESIGN.md) から選ぶ。固定コマンドの共通原則だけを確認して終わらず、**選択したジャンルの動詞・対象階層・解決の核・PoCへ照合する**。

混成作品は主パレットを一つ定め、実際に併用する副パレットを列挙する。推理へ冒険パレットを、脱出へRPG用対応を、根拠なく流用しない。

### 探偵・推理パレット

```text
あたりをみる
しらべる → 対象
きく → 人物
なにかきく → 人物
なにかとる
ばしょいどう → 場所
でんわをかける
つきつける → 人物 → 証拠
```

解決の核は、集めた証拠を人物へ `つきつける` ことで矛盾・反応を世界内に実演すること。`knows_*` の取得後に「アリバイの矛盾を暴く」「真犯人を追及する」等の完成済み解決コマンドを湧かせない。

未入手の証拠を証拠サブメニューに出さないことは許容する。誤った人物×証拠には、GMの採点でなく人物の反応や証拠との不一致を返す。構造は [detective_command.ink](../../../../docs/06-reference/scenarios/detective_command.ink) と比較する。

### 脱出パレット

```text
しらべる → 見えている場所・物 → 発見済みの部位
とる → 露出している物
つかう → 所持品 → 発見済みの対象
おす・うごかす → 発見済みの可動部・操作部
もちもの → 所持品と既に観察した事実の確認
ばしょいどう → 部屋・安定した視点
```

解決の核は道具と対象の組み合わせ。`しらべる` は見えているランドマークから発見済みの部位へ段階化し、入力装置は `おす・うごかす → 入力装置 → 値を入力する` から自由入力へ進める。詳細は [escape_exploration_gimmicks.md](../../ink-scenario-creator/references/escape_exploration_gimmicks.md)、探索量と依存の独立監査は [escape_exploration_review.md](./escape_exploration_review.md) を使う。構造は [escape_room.ink](../../../../docs/06-reference/scenarios/escape_room.ink)、[escape_mansion.ink](../../../../docs/06-reference/scenarios/escape_mansion.ink)、作例 [sealed_guest_room.ink](../../../../docs/06-reference/scenarios/sealed_guest_room.ink) と比較する。

### 冒険パレット

```text
しらべる → 対象
あける・しめる → 対象
とる・すてる → 対象
つかう → 道具 → 対象
たたく → 対象
はなす → 対象
うごく → 場所
もちもの
```

解決の核は探索、道具の組み合わせ、移動、状態管理。構造は [adventure_command.ink](../../../../docs/06-reference/scenarios/adventure_command.ink) と比較する。サバイバルRPGはこの冒険パレットを基礎に、§7の正確な対応を追加検査する。

### すべてのパレットで固定されるもの

- 選択したジャンルのトップレベル動詞語彙
- 同じ働きかけを同じ動詞へ畳む規則
- 動詞から人物・証拠・道具・対象へ進む階層
- 解決の核となる働きかけ

### 変えてよいもの

- 場所ごとの人物・物・移動先
- 現在入手している証拠・道具
- 世界状態による結果
- 対象が存在しない場所で、既知動詞を非表示にすること
- 未入手の証拠・道具をサブメニューに出さないこと

### 表示制御の例外

`つぎへ` はページ停止点を作る表示制御用の例外であり、ゲーム内動詞ではない。純粋なページ停止点で原則1択として使い、謎・移動・戦闘のゲートを代替させない。

### 行動結果からsceneへ入り直す境界

adventure-mcp の `GameSession` は、選択肢・入力待ち・終端まで Ink の本文と divert を一つの `scene` に結合する。したがって、行動結果の後で導入・状態説明を出す場所／sceneへ入り直す経路は、knotが分かれているだけでは表示境界にならない。

Applicableな完成Inkでは、実際の `GameSession.scene`／`choices` で次を監査する。

| 代表経路 | 結果ページ | `つぎへ` 後 | 判定 |
|---|---|---|---|
| 前提不足の移動ゲート | 失敗理由だけ | 元の場所本文＋固定コマンド | |
| 成功した移動ゲート | 移動結果だけ | 移動先本文＋固定コマンド | |
| `おす・うごかす` の成功・失敗 | 操作結果だけ | 現在地本文＋固定コマンド | |
| `つかう` の正用途・誤用途・組み合わせ | 使用結果だけ | 現在地本文＋固定コマンド | |
| `とる`／`もちもの`／入力結果 | 取得・一覧・正誤結果だけ | 現在地本文＋固定コマンド | |

PASS：

- 結果ページに、次に入る場所の導入・状態説明が混ざらない。
- 純粋な結果ページの choices は `つぎへ` 1件である。
- `つぎへ` の後に、期待した場所本文と固定コマンドが出る。
- 結果ページ時点の公開現在地が本文と矛盾しない。
- 結果本文を挟まない通常移動・キャンセルは、選択自体を停止点として直接場所本文へ進む。
- 調査結果から本文なしメニュー／短い対象質問へ戻る経路には、冗長な `つぎへ` を置かない。

FAIL：

- `失敗文 -> 本文あり場所ハブ` のように、結果と場所説明が同じ MCP `scene` へ連結される。
- 逆に、すべての divert や全サブメニュー復帰へ機械的に `つぎへ` を足し、操作を不必要に細切れにする。
- knot境界だけを見て「別scene」と判定し、実行時の `scene`／`choices` を確認しない。

主コマンドループ全体で系統的に違反する場合は Major のMCP／表示契約不備候補とする。孤立した一件は、文章の混線量、誤読、操作テンポへの実害に応じて重大度を決める。

## 4. トップレベル動詞のドリフト監査

各ハブ・場所・戦闘メニューについてトップレベル選択肢を抽出する。

| ハブ・場所 | トップレベル動詞 | 新しい一時動詞 | 既存パレットへ畳めるか | 判定 |
|---|---|---|---|---|

次を不適合候補として扱う。

- `排水する`
- `重ねる`
- `鍛える`
- `振り子を止める`
- `子守歌で記憶を呼び戻す`
- `本来の儀式を思い出させる`
- クラス名つきの必殺技・連携技

それらがその場限りのトップレベル解決コマンドなら、選択したジャンル別パレットの既存動詞へ畳めないかを確認する。推理では `つきつける→人物→証拠`、脱出では `つかう→道具→対象`、冒険では `しらべる／つかう／たたく／うごく` 等、解決の核まで含めて照合する。

動詞数を減らすこと自体は目的ではない。異なる働きかけまで無理に統合しない。判定基準は、リポジトリのジャンルパックが宣言したパレットと「同じ働きかけか」である。

## 5. outcome-gating 監査

主要な謎、前提ゲート、ボス、危険地形ごとに次を埋める。

| 解法・突破条件 | 固定動詞 | 対象経路 | 前提状態 | 前提前の結果 | 前提後の結果 | 判定 |
|---|---|---|---|---|---|---|

### PASS

- 自然な操作経路が、正解を知る前から存在する。
- 前提不足で試すと、世界内の理由が分かるフェアな空振り・失敗になる。
- 手がかり、道具、装備、状態がそろうと、**同じ操作経路**の結果が成功へ変わる。
- 誤った動詞×対象や道具×対象には、作者の採点でなく物理・人物反応・制度上の理由が返る。

### FAIL

- `knows_*` や進行フラグ取得後にだけ、完成済みの解決文が選択肢として現れる。
- 解禁された選択肢の文章が、プレイヤーが行うべき発見・推論・操作を全部説明する。
- 正しい行動が現れたこと自体が、どれが正解かを教える。
- 解法専用コマンドを選ぶだけで、対象選択や世界への実演がない。
- 間違いが「空振り」「決め手ではない」等のGM採点だけで返る。

### 条件付き選択肢の読み方

条件付きで対象が現れることを一律に禁止しない。

- 道具未所持のため `つかう` の道具候補に出ない：許容
- 破壊済み・取得済みで対象が世界から消えた：許容
- 知識フラグ取得後にだけ「正しい儀式を行う」がトップレベルに出る：不適合
- 観察によって物理的な対象の存在に気づき、以後 `しらべる→対象` が可能になる：対象発見として評価し、解決文の出現とは区別する

## 6. N択コミットの境界

### FAIL

- N択メニューが、謎を解くための発見・推論・操作を供給する。
- 選択肢本文が、プレイヤーが生成すべき解法を完成文で述べる。
- 正解順序、正しい道具、敵の弱点、証拠の意味を、候補文から再認するだけで突破できる。
- クラスごとに「この能力で安全に突破する」という正解文を表示し、固定コマンドによる実演がない。

### ALLOW

- 調査・推理・世界への働きかけが完了した後の最終告発。
- 既知の結果を踏まえたエンディング決断。
- 誰を助けるか、何を犠牲にするかという価値判断。
- 既に実演済みの解を最後に確定する確認。

ただし最終コミットであっても、それまで説明されていない因果規則・代替解法・魔法法則を選択肢本文に初出させてはならない。

## 7. RPGでの正確な対応

RPGパックがApplicableの場合も、専用戦闘UIや新規動詞を作らず冒険パレットへ畳む。

- **通常戦闘・武器による決め手**：`たたく→敵`
- **非武器道具による決め手**：`つかう→道具→敵`
- **消耗品による回復**：`つかう→道具→自分`
- **回復地点の利用**：`うごく→場所`
- **公開状態の確認**：`もちもの`

### 動詞の選び方

- 判断が「どの道具を使うか」にない場合、手にある得物で `たたく→対象`。
- 判断が「どの道具を使うか」そのものである場合、`つかう→道具→対象`。
- 剣・素手は `たたく`、鍵・護符・鏡・触媒・消耗品は `つかう`。

次を新しいトップレベル解決コマンドとして出さない。

- クラス専用攻撃
- `たたかう`
- `やすむ`
- `にげる`
- 連携技
- 歌や儀式の完成済み結論

作品固有のメカニクスを禁じるのではない。**新規性は固定動詞の対象・組み合わせ・結果で表現する**。

## 8. ジャンル別PoCとの比較

### detective_command.ink（探偵・推理）

確認点：

- `あたりをみる／しらべる／きく／なにかとる／ばしょいどう／もちものをみる／つきつける` のトップレベル動詞が安定している。
- 現在地によって人物・物・移動先だけを出し分ける。
- 入手した証拠を `つきつける→人物→証拠` で世界内に提示する。
- 誤った人物×証拠へフェアな反応を返す。
- 真相を知った後に「矛盾を暴く」等の解決専用コマンドを追加しない。

### escape_room.ink（脱出）

確認点：

- ハブの動詞が安定している。
- `つかう→道具→対象` で働きかける。
- 真鍮の鍵を扉に使う、鉄の鍵を引き出しに使う等の誤組み合わせが、世界内の理由で空振りする。
- 鉄の鍵を扉に使ったときだけ解錠する。

### sealed_guest_room.ink（脱出・作例）

確認点：

- 六動詞が順序付き部分集合として安定し、ランドマークから部位へ段階的に発見する。
- 入力装置、順序操作、最終操作が、手がかり取得前後で同じ経路に残る。
- 誤入力、誤順序、誤使用の後も同じ経路から再試行できる。
- 移動ゲート、操作、道具使用、取得、入力結果が、本文あり場所ハブへ入る前に結果ページで止まり、場所説明を同じ `scene` へ連結しない。
- 通常移動、キャンセル、調査メニュー復帰には冗長な `つぎへ` がない。
- `public_status` が `place` だけで、所持品・発見・段階・正解値を公開しない。
- 具体的な正解値や正解順序はレビュー本文へ転記しない。

### adventure_command.ink（冒険）

確認点：

- 探索、取得、道具使用、打撃、会話、移動、状態確認を冒険パレットへ畳む。
- 場所が変わってもトップレベル動詞を増減させず、対象と結果で場面固有性を表現する。

### legendary_forge_cmd.ink（冒険＋推理）

確認点：

- 手記による演繹だけでは候補が一つに決まらない。
- 鋼・銀の刃を鱗片へ実際に `つかう` ことで、帰納的に差を発見する。
- 得物を組む行為も `つかう→道具→対象` で実演する。
- 準備状態によって守護者への結果が変わる。
- 正解を知った後に「銀の武器で倒す」という解決専用トップレベル動詞を追加しない。

疑わしい実装は、作品に適用したジャンル別パレットと対応するPoCへ構造比較する。

## 9. レビュー出力

コマンドハーネスの指摘には次を含める。

- 選択したジャンル別パレットと、その適用理由
- 場所ごとのトップレベル選択肢
- 選択した固定パレットとの差分
- 新しく湧いた解決専用コマンド
- 正解前後で同じ操作経路を使えるか
- N択が最終コミットか、解決過程の代替か
- 該当する正規参照とPoC
- `PASS` / `FAIL` 判定

主構造の謎・脱出探索・RPGループが固定コマンド＋outcome-gatingを採用していない場合は、局所的なUI問題でなく **Blocker候補**として扱う。脱出・探索の量と依存の薄さは、別にEscape Explorationレビューで判定する。
