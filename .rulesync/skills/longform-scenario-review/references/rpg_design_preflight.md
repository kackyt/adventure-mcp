# RPG設計プレフライト

サバイバル・RPGの設計票を、Ink実装前に壊すためのレビュー。完成品の文章品質やコンパイルを評価するのではなく、プレイヤーが「誰として、なぜ危険を冒し、何を達成するか」と、資源管理のゲームが因果的に成立しているかを判定する。

## 1. 適用条件と完成品レビューとの違い

次のいずれかなら適用する。

- 対象が [ink-scenario-creatorのRPG設計票](../../ink-scenario-creator/references/rpg_player_contract.md)
- ユーザーがRPG設計プレフライトを指定した
- サバイバル・RPGのプロット、人物、資源表を実装前にレビューする

このモードでは `.ink`、生成JSON、シナリオ固有テストがまだ存在しなくてよい。コンパイル、MCP実機、到達性は `NOT RUN（設計段階）` とし、それ自体を欠陥にしない。

ただし、実装後に確認すべき項目が設計票に無ければ指摘する。設計プレフライトの `READY` は完成承認ではなく、Ink実装へ進んでよいという判定である。完成後は通常の `longform-scenario-review` をもう一度実施する。

設計者の意図、後で書く予定の説明、未記載の設定で不足を補わない。設計票に書かれた公開情報と因果だけを証拠にする。

## 1.5 企画・ゲーム先行ゲート

[game_first_concept_gate.md](../../ink-scenario-creator/references/game_first_concept_gate.md) を先に実施する。開幕契約、資源式、固定コマンドが成立していても、企画そのものが弱ければ `READY` にしない。

### A. 既存差分

`web/scenarios/scenarios.json`、同ジャンルの既存作、`docs/02-design/` の直近設計、現在の会話で却下された案から近い3作以上を選び、次を比較する。

| 作品・案 | 主人公型 | 目標型 | 基本ループ | 判断型 | 進行構造 | 資源圧 | 判定 |
|---|---|---|---|---|---|---|---|

主人公型・目標型・基本ループ・判断型・進行構造のうち3軸以上が最も近い直近作と同じならMajorとする。舞台名、敵名、資源名だけの変更を差分に数えない。ユーザーが「既存作と違う切り口」を求めた場合は必須契約として扱う。

### B. 30秒ピッチとゲーム単体

次を固有名詞なしの二文で書けるか確認する。

1. プレイヤーが何を見て、何を判断し、何を操作して勝つか。
2. 誰が何を望み、失敗すると何を失うか。

さらに、物語固有名を外しても30秒ごとの基本ループ、上手いプレイと雑なプレイの差、3分以内の固有判断を説明できるか確認する。

次をBlockerとする。

- 固有名詞や世界設定を外すと、何をして勝つゲームか説明できない。
- HP、回復、戦闘という名だけあり、プレイヤー判断がない。
- 物語の意外性・感動・設定の珍しさが、ゲームループの代わりになっている。

### C. おつかい・局面差

目的欄が危機と望む状態だけを示し、正しい動詞・対象・順序を渡していないか確認する。各局面を次で比較する。

| 局面 | 新しい観測 | 比べる候補 | 判断基準 | 操作 | 結果変化 | 前局面との差 |
|---|---|---|---|---|---|---|

次をMajorとする。

- NPCや目的欄の指定どおり対象を操作するだけで進む。
- 「頼まれる→取る→届ける／起動する」を主構造で反復する。
- 全対象を観察すると解決操作が自動成功する。
- 同じ認知規則を対象名だけ変えて3回以上繰り返す。
- フェーズ数や敵数を、意味ある判断数として水増しする。

### D. 認知負荷収支

| 新語・新規則 | 教える時点 | 再利用回数 | 生まれる異なる判断 | 既知表現へ代替可能か | 判定 |
|---|---|---:|---|---|---|

世界前提、操作文法、資源則、局面判断の四層を同時に新しくしていないか確認する。新要素一つにつき、少なくとも二つの異なる局面判断または一つの大きな戦略判断へ効かせる。

次をMajorとする。

- 開幕で三つ以上の未知語・新規則の理解が必要である。
- 長く説明した規則が一度の指定操作にしか使われない。
- 認知負荷は高いが、覚えた後の操作・判断が単調である。
- 設定・操作・資源のすべてを新しくし、練習前に実戦判断を要求する。

### E. 難易度と尺

設計段階では目標値、完成後はコールドプレイ実測を使う。

| 項目 | 目標 | 根拠となる局面・手数 | 完成後の測定 |
|---|---|---|---|
| 難易度 | Easy / Normal / Hard | | 試行数、迷い、観察なし正解数 |
| 尺 | 分 | | ツール待ちを除くクリア時間 |

Normalは、複数事実の統合または複数のもっともらしい資源・経路判断を必要とする局面が複数あり、初見の安全な迷いと回復が生じること。大半が一観察・一発正解ならEasyである。完成実測がEasy相当なのにNormalを維持する場合はMajorとする。尺不足を同型局面や本文量で埋める案もMajorとする。

## 2. 開幕契約テスト

初見プレイヤーが、最初の意味あるゲーム内選択までに次へ答えられる設計か確認する。

| 質問 | 設計票の根拠 | 開幕で示す方法 | 判定 |
|---|---|---|---|
| 自分は誰か | | | PASS / FAIL |
| 事件前から何を欲しているか | | | PASS / FAIL |
| なぜ今ここにいるか | | | PASS / FAIL |
| 今何を達成するのか | | | PASS / FAIL |
| どうなれば成功か | | | PASS / FAIL |
| 失敗すると主人公自身が何を失うか | | | PASS / FAIL |
| なぜ危険を冒して帰らないか | | | PASS / FAIL |

一つでもFAILならBlockerとする。

「村を救う」「世界を救う」は任務であり、主人公が行う理由ではない。報酬、職務、家族、生存、名誉、奪還等の個人的利害と任務が因果でつながっているかを見る。

「主人公の正体を後で明かす」作品でも、現在の社会的立場、当面の欲求、行動理由、成功条件は開幕で必要である。過去の秘密と現在の操作契約を混同しない。

## 3. 主人公置換テスト

次を具体的に答える。

> 主人公を「通りすがりの強い冒険者」へ置き換えると、どの任務、情報、能力、利害、関係、結末が成立しなくなるか。

何も壊れない場合、主人公の名前、職業、過去、動機は飾りである。

次をFAILとする。

- 主人公固有の能力が、各障害の無償成功文にしか使われない
- 主人公の過去が回想とエピローグの差分にしか出ない
- 主人公の職業を変えても同じ情報、経路、損耗、報酬になる
- 主人公の社会的立場がNPCの反応やアクセス範囲を変えない

主人公を簡潔な固定人物にすることは許容する。重要なのは設定量でなく、設定が現在のプレイを変えることである。

## 4. 動機削除テスト

次を具体的に答える。

> 設定した報酬、名声、家族、記憶、責任等を削除すると、主人公はなぜ同じ場所へ行き、同じ危険を冒せなくなるか。

動機を削除してもNPCに頼まれただけで同じ進行をするなら、動機は飾りである。

次をFAILとする。

- 「金貨が欲しい」があるが、依頼主、契約内容、支払い条件がない
- 「記憶を取り戻したい」があるが、事件との因果、手がかり、達成条件がない
- 「人助け」が性格説明だけで、誰をどこまで救うか決まらない
- 動機別の違いが回想、台詞、エピローグだけ

偽の動機選択がある場合はMajorとする。深く分岐できないなら、主人公と動機を固定する修正を優先する。

## 5. 帰還可能性テスト

危険を知った最初の地点を特定し、次を問う。

> その時点で、主人公が任務を放棄して帰る方が合理的ではないか。

継続理由として認める例：

- 明示された契約と必要な報酬
- 帰路の封鎖と本人の生存
- 家族、故郷、地位等の具体的損失
- 主人公にしかできない能力・権限
- それまでの観測から本人が自ら引き受けた使命

次だけでは不足する。

- NPCがお願いした
- 主人公は善人である
- 物語の主人公だから
- 世界が危険だから
- 同行者が魅力的だから

帰る方が合理的なまま進行させる設計はBlockerとする。

## 6. 使命の因果列

次を埋める。

| 段階 | 主人公の目的 | 観測した事実 | 目的が次へ変わる理由 | 判定 |
|---|---|---|---|---|
| 事件前 | | | | |
| 開幕任務 | | | | |
| 当事者化 | | | | |
| 目的更新 | | | | |
| 最終使命 | | | | |
| 決戦での実演 | | | | |
| 結末 | | | | |

NPCが次の場所を指定するだけ、章を終えたので次章へ行くだけ、作者だけが知る真相でつながるだけならFAILとする。

最終決戦前に、プレイヤーが「何のために戦うか」「何を達成すれば勝ちか」を説明できなければBlockerとする。最終選択肢で使命、代償、代替解法、世界法則を初出させない。

使命が最初から最後まで一定でもよい。その場合は、各章が同じ任務のどの前進なのかを示す。

## 7. 偽選択テスト

職業、出自、動機、クラス等の選択ごとに比較する。

| 選択候補 | 情報 | 固定コマンド／対象 | 経路 | 資源収支 | 社会的立場 | 利害・結末 | 判定 |
|---|---|---|---|---|---|---|---|

各候補が次のうち二つ以上を変えなければ、選択を削除する。

- 利用できる情報
- 固定コマンドの対象・組み合わせ
- 攻略経路
- 支払う資源
- 装備・成長
- NPCとの立場
- 中間目標
- 最終的な利害
- エンディングの意味

全職に対応する無償成功文を各障害へ置き、どの職でも無傷で同じ場所へ戻す構造はMajorとする。文章が違うことをゲーム差と扱わない。

## 8. 関係獲得テスト

主要NPCごとに次を確認する。

| NPC | 初対面 | 協力の実利 | NPCの貢献 | 主人公の貢献 | 関係変化の出来事 | 好意なしの攻略 | 判定 |
|---|---|---|---|---|---|---|---|

次をMajorとする。

- 素性不明の同行者を、登場直後から大切な人物として扱わせる
- NPCが役立つ前に、献身や無条件の信頼を要求する
- 作者が好む台詞に `trust`、好感度、善悪度を加点する
- 未説明の関係値を最良EDや真EDの条件にする
- NPCを警戒する合理的な選択を格落ちルートとして採点する

関係は共同作業、救援、約束の履行、能力の相互補完等の観測可能な出来事から変化させる。関係を深めないプレイヤーにも、任務達成の合理的経路を残す。

## 9. 主題実演テスト

次を埋める。

| 主題 | 観測する事実 | プレイヤー操作 | 世界内の結果 | プレイヤーが形成できる理解 | 判定 |
|---|---|---|---|---|---|

次をMajorとする。

- 哲学的な完成回答をN択で並べる
- 作者推奨回答へ内部スコアを与える
- NPCが主題を講義し、プレイヤーの操作に対応しない
- 主題に同意すると真ED、疑問を持つと格落ちEDになる
- 選択肢の文章が主人公の結論を先に決める

価値判断のN択そのものは禁止しない。どの選択も異なる実在の利害と結果を持ち、作者の正誤採点になっていない場合は許容する。

## 10. RPG資源経済の事前検算

実装前でも次を数値で出す。

| 開始主資源 | 正解装備・ノーミスの必須通行料 | 回復量 | 回復数 | 総供給 | 想定ミス | 余剰マージン |
|---:|---:|---:|---:|---:|---:|---:|

加えて、各消費を任務へ接続する。

| 区間・障害 | 任務上の目的 | 正解時の必須消費 | ミス時の追加消費 | 補給 | 無料代替 | 判定 |
|---|---|---:|---:|---:|---|---|

次をMajorとする。

- 必須通行料が開始主資源以下
- ノーミスで携行回復が不要
- 全障害を無料の職業専用回答で回避できる
- 強力な消耗品より無料回答が常に優れる
- 決戦直前の全回復で道中収支が消える
- 資源消費が任務の前進や試行の価格になっていない

詳細は [rpg_economy_review.md](./rpg_economy_review.md) を使う。

## 11. 固定コマンド計画

実装前に、場所ごとのトップレベル動詞と主要outcome-gatingを表にする。

| 場所 | トップレベル動詞 | 対象 | 前提状態 | 前提前の結果 | 前提後の結果 | 判定 |
|---|---|---|---|---|---|---|

サバイバル・RPGは冒険パレットを使う。障害ごとの完成済み解決文、クラス専用技、答えN択、知識取得後にだけ湧く解決コマンドを計画している場合はBlocker候補とする。

詳細は [fixed_command_harness_review.md](./fixed_command_harness_review.md) を使う。

## 12. 重大度とREADY判定

### Blocker

- 開幕契約の七問に一つでも答えられない
- 主人公が任務へ関与する因果がない
- 危険を知った後に帰る方が合理的なまま
- 最終使命が決戦前に成立していない
- 作品の約束が具体的な操作、資源、目標を説明しない
- 主構造を固定コマンド＋outcome-gatingで表現する計画がない
- 固有名詞を外すと、プレイヤーが何をして勝つゲームか説明できない

### Major

- 職業・出自・動機が文章差分だけの偽選択
- 関係形成前に好意、信頼、献身を要求する
- 作者推奨回答を関係値、善悪度等で採点する
- 未説明の関係値を最良ED条件にする
- 主題を完成済み回答のN択で説明する
- 無料解答がRPG資源経済を消す
- 通行料が開始主資源以下で回復が不要
- 主構造が指示消化のおつかい／チェックリストである
- 同じ認知操作を対象名だけ変えて反復し、局面数を水増しする
- 直近作と主人公型・目標型・基本ループ・判断型・進行構造の3軸以上が重なる
- 新語・新規則の認知負荷が高いのに、生まれる判断が一種類である
- 完成コールドプレイがEasy相当なのにNormal表記を維持する

### Moderate

- 使命の更新は成立するが弱い
- 主人公固有要素の一部が差分テキストに留まる
- NPCの貢献と関係変化の間が遠い
- 資源供給や余剰マージンに局所的な偏りがある

### READY

BlockerとMajorが0件の場合だけ `READY` とする。点数、文章の魅力、設定の独創性でハードゲート違反を相殺しない。

## 校正用失敗セット

次をすべて検出できることを確認する。ファイル名や固有名を判定条件にしない。

- 主人公が「旅人」だけで、名前・来訪経緯・個人的利害がない
- 「村を救う」と書いてあるが、主人公が救う理由がない
- NPCの依頼だけで危険な任務を継続する
- 職業ごとに同じ無償成功文が用意される
- 動機が回想とエピローグの文章差分だけ
- 見知らぬ同行者への好意を最良ED条件にする
- 哲学的回答を内部の信頼度・決意度で採点する
- 三つのアイテムで十分と説明しながら、未説明の関係値を第四条件にする
- 最終選択で初めて使命と世界法則を提示する
- ノーミス必須通行料が0で、回復材を使わずボスまで勝てる
- 固有名詞と専門設備の説明を外すと、ゲームの目的と基本ループが残らない
- 複数の未知語と新規則を覚えさせるが、全区間で同じ指定操作を繰り返す
- 直近の成功作と同じ見習い・資格・大会・連戦を、舞台名だけ変えて再利用する
- 一観察・一発正解の局面が大半なのにNormalと自己申告する
