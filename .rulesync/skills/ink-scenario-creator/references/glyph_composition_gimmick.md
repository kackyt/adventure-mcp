# グリフ合成ギミック（千切れた部品を重ねて字にする）

千切れた断片を**上下/左右に重ねると別の字になる**——火＋火＝炎、山＋石＝岩、日＋月＝明。
暗号（[cipher_gimmick.md](./cipher_gimmick.md)）が「規則を帰納」させるのに対し、こちらは「**形の見立て**」で解かせる。
アハ体験の回収ルールは **`puzzle_design.md` §6.7 が最優先の前提**（本書はそのグリフ版の具体レシピ）。

## 1. なぜ漢字合成か（可読性の ground-truth）

合成の肝は「重ねた結果がちゃんと読めるか」。ここは**AI の想像で判断してはいけない盲点**（`[`+`)`→`D` が読めるかを頭の中で決めると外す）。
だから可読性は**実在の漢字分解＝人手検証済みの合成辞書**に委ねる：

- **漢字はそれ自体が数万件の検証済みグリフ合成表**。⿱（上下）／⿰（左右）構成の字を使えば、
  「上下に千切れた」「左右に千切れた」札がそのまま作れる。可読性を決めたのは3000年の書字史であって私ではない。
- データ源は Unicode の **IDS（Ideographic Description Sequence）**（Unihan/CHISE/IDS プロジェクト）。
  2部品・各部品が独立字・きれいな⿱/⿰…で絞れば数百件が即出る。
- **「先に作って千切る」（render-then-tear）＝元が一字だから重ねれば必ず読める**。順方向に断片を"合成"して
  可読性を賭けるより、逆方向（完成字→分割）が安全。

## 2. 断片の割り方

| 破れ方 | 構成 | 例（合成字＝部品／部品） |
| --- | --- | --- |
| **上下に千切れ** | ⿱ | 炎＝火／火、 岩＝山／石、 泉＝白／水、 男＝田／力、 花＝艹／化、 雲＝雨／云、 星＝日／生、 志＝士／心 |
| **左右に千切れ** | ⿰ | 林＝木／木、 明＝日／月、 好＝女／子、 休＝亻／木、 鳴＝口／鳥、 make: 部首＋旁 |
| **入れ子** | ⿴等 | 園・国・問…（難度高。多くは⿱/⿰で足りる） |

複数文字に伸ばすなら、**各文字を同じ構成（全部⿱ or 全部⿰）で揃える**と、1本の破れ線が全字を上部品/下部品に割る
（例：上片＝山 白／下片＝石 水 → 岩 泉）。

## 3. 解かせ方（§6.7 の厳守。ここを外すとアハが消える）

`puzzle_design.md §6.7` をグリフ合成に落とすと：

- **合成はプレイヤーの脳内で起こす。** 断片（素の部首＝火・山・石…）を**別々の場所に配って見せるだけ**。
  「重ねる」ボタンも、重ねた結果のグリフ表示も作らない（＝カットシーン禁止）。読むのはプレイヤー。
- **合成後の字を入力・選択させない**（並べたら再認N択）。読み取った先は**世界の一点を描写**し、
  プレイヤーは**そこを探し当てて `しらべる`／`つかう`** で実演する。固有名の既知地への移動にしない（場所縛り＆ラベル漏れ）。
- **カモフラージュを十分に置く。** 正解の一点を凡庸な interact 候補に埋める。少ないと解かずごり押しで当たる。
- **空振り・メタ禁止。** 外れた候補は独立した本物の diegetic 内容を返す。「外れ」の signposting も謎への注釈も出さない。

> つまり誤答判定・スロット入力・開封演出は**要らない**。断片を配り、正解の一点を本物のカモフラージュに紛れさせ、
> 到達は既存の探索動詞のみ。暗号封印（誤入力→無音失敗）とは設計が根本的に違う。

## 4. フェアネス（グリフ固有）

- **各部品が単体で意味を持ち、物証として置ける**（火＝焦げ跡、水＝井戸、石＝庭石…）。片割れから全体が割れない。
- **破れ線を"意味の切れ目"とズラす**（横に読むと無意味＝山白/石水。重ねて初めて地名）。「横読みでなく重ねる」の気づきが山場。
- **合成字の読みは"描写できる一点"を指す**（例：高台の・水際の・白っぽい石）。命名でなく場所の記述に落とす（§6.7）。
- **可読性は IDS 由来のみ**。うろ覚えで字の構成を作らない（岳・岸などの分解は DB で確認）。

## 5. 生成（構想：gen_torn_layout）

`cipher_gimmick.md` の生成器と対をなす想定。目標語（⿱/⿰ 構成の字列）を渡すと：

1. **IDS 分解**で各字を上部品/下部品（or 左/右）に割る（人手検証済みの可読性）
2. 各部品が**独立字・物証化できる**かを点検、破れ線が全字を割れるか（構成の揃い）を検査
3. **カモフラージュ候補**（同部首を持つ紛らわしい実在字／無関係な interact 対象）を IDS から供給
4. 断片配置・カモフラージュ配置の **Ink 雛形**（§6.7 準拠：合成表示なし・入力なし・探し当て interact）を出力

> **未実装**。まずは同梱の**手起こし厳選表**（§2 の例）で運用でき、100件規模へ伸ばすときに IDS 取得＋機械抽出へ移す。
> 可読性の最終確認は不要（漢字分解が ground-truth）だが、**物語接地・カモフラージュ密度・場所描写化**は人間が見る。

## 6. 最小例（設計メモ用・解は本文に出さない）

上片＝2つの部首、下片＝2つの部首を別々の場所で拾わせ、重ねると地名の2字になる。プレイヤーはそれが指す
「高台の・水際の・白い石の一点」を、周囲の多数の本物のカモフラージュ（無関係な石・井戸・祠…）の中から
探し当てて `しらべる`。ゲームは合成字も地名も一度も印字しない（§6.7）。
