# ゲーム先行の企画ゲート

新作の企画を、物語設定や実装へ進む前に選別する。目的は「破綻していない案」ではなく、初見で遊びが伝わり、既存作と違う判断を楽しめる案だけを残すことである。

## 1. おまかせ時の候補生成

おまかせモードでは、最初の思いつきをそのまま採用しない。内部で最低3案を作り、次を互いに変える。

- プレイヤーの立場と願望
- 一回の基本ループ
- 主な判断材料
- 進行の形
- 主資源または失敗圧
- 舞台とトーン

3案をユーザーへ順番に相談する必要はない。後述のゲートで比較し、最も強い1案だけを設計票へ進める。どの案も弱ければ候補を作り直す。

## 2. 既存作・直近案との差分

候補作成前に、少なくとも次を確認する。

- `web/scenarios/scenarios.json` と同ジャンルの既存作品
- `docs/02-design/` の直近設計票
- 現在の会話で採用・却下された案と、その理由

近い作品を最低3本選び、次の指紋を表にする。

| 作品・案 | 主人公の型 | 目標の型 | 基本ループ | 判断の型 | 進行構造 | 資源圧 | 物語の核 |
|---|---|---|---|---|---|---|---|

舞台名や敵名だけ変えても差分に数えない。次の中核5軸のうち3軸以上が最も近い直近作と同じなら、別案へ替える。

1. 主人公の型（見習い、親、職人、指揮役など）
2. 目標の型（資格獲得、救出、配送、防衛、脱出など）
3. 基本ループ（連戦、探索統合、拠点運営、追跡、護衛など）
4. 判断の型（予兆対応、資源配分、経路選択、組み合わせ、交渉など）
5. 進行構造（五番勝負、一方向区間、往復探索、波状防衛、日程管理など）

直近作で使った「見習いが試験や大会を勝ち抜いて資格を得る」のような組み合わせは、通りやすい成功型でも連投しない。保持するのは、目的の明快さやゲーム先行という品質であり、主人公・大会・資格という表面ではない。

## 3. 30秒ピッチ

固有名詞を使わず、次の二文を書けることを必須とする。

1. **ゲーム文**：プレイヤーが何を見て、何を判断し、何を操作して勝つか。
2. **物語文**：誰が何を望み、失敗すると何を失うか。

文型：

> 〈観測〉を読み、〈比較する判断〉を行い、〈固定操作〉で〈勝利状態〉を作る。〈具体的な立場の人物〉が〈事件前からの願い〉のために動き、失敗すると〈本人の損失〉が起きる。

この段階では、造語、専門設備、歴史講義、超常現象の例外規則を使わない。二文で説明できない企画は、説明文を増やさず核を単純化する。

### 固有語負債

最初の意味ある操作前に、理解必須の未知語は原則0、必要でも1つまでにする。普通名で説明できる装置へ複数の独自名を付けない。未知語を取り除くと目的や危険が分からなくなる企画は、プレイヤーが設定講義へ入場料を払う構造なので棄却する。

## 4. ゲーム単体テスト

物語固有名をすべて外し、次へ答える。

- 30秒ごとに何を見て、どの候補を比べ、何を決めるか。
- 上手いプレイと雑なプレイは、操作と結果の何が違うか。
- 3分以内に、この作品ならではの判断を一度実演できるか。
- 物語文を半分に削っても、ゲームループだけで遊びたいと思えるか。
- RPGを名乗る理由がHP表示だけでなく、準備・成長・配分・戦闘判断のどこにあるか。

答えが「次の指示を読み、指定物を指定場所へ使う」だけなら不合格。物語の感動、世界観の珍しさ、結末の意外性でゲームの弱さを相殺しない。

## 5. おつかい・チェックリスト検査

次のいずれかが主構造へ広がる案は作り直す。

- NPCまたは目的欄が、毎場面の対象・動詞・順序まで指示する。
- 各区間が「頼まれる→物を取る→届ける／起動する」の同型である。
- `しらべる`を全対象へ実行すると、解決操作が自動成功する。
- 場所名と対象名だけ変え、同じ認知規則を3回以上繰り返す。
- 主人公が自分で状況を変えるのでなく、依頼一覧を消化する。

目的欄には危機、放置結果、望む世界状態を書く。正しい動詞、対象、順序は書かない。観察は答えを配るのでなく、複数の事実から判断を作る材料にする。

## 6. 意味のある局面表

フェーズ数、敵数、ノット数をボリュームとして数えない。各局面を次で記録する。

| 局面 | 新しく観測する事実 | 比べる候補 | 今回の判断基準 | 操作 | 結果で何が変わるか | 前局面との差 |
|---|---|---|---|---|---|---|

同じ判断基準で表示された対象を追うだけなら一つの局面として数える。同じ固定動詞を再利用してよいが、対象関係、判断材料、リスク、操作後の世界変化のいずれかを変える。

目安として、中ボリュームでは次を満たす。

- 中心ループを学ぶ局面
- 学んだ規則を別条件で使う変奏
- 二つ以上の既知要素をまとめる山場
- 資源または経路の実効的な配分判断

## 7. 物語の既定値

ユーザーが複雑な物語を求めていない限り、物語は普通の因果を優先する。

- 主人公の目的は身近で具体的にする。
- 危険と損失は、その場で見えるものにする。
- 中心設定は一つに絞り、ゲーム操作へ直接効かせる。
- 反転、死後世界、記憶喪失、複雑な制度、親子の過去などを「深み」の既定値にしない。
- 新奇さは設定語の数でなく、プレイヤーが行う判断の組み合わせから出す。

ただし、普通の物語を同じ主人公型へ固定しない。防衛、追跡、奪還、調査、運営、護衛、潜入、採集、競技など異なるプレイヤー幻想を候補にし、直近作と同じ型を避ける。

## 8. 認知負荷の予算

「今まで見たことがない」は無条件の長所ではない。未知の世界、未知の用語、未知の操作、未知の資源則はすべて、遊ぶ前に理解コストを要求する。その支払いに見合う判断の広がりがなければ棄却する。

### 一度に新しくしない

次の四層を分ける。

1. **物語前提**：世界、立場、目的、危険
2. **操作文法**：動詞、対象階層、画面の読み方
3. **ゲーム規則**：資源、勝敗、状態変化
4. **局面判断**：各場面で比べる候補

中心となる新規性は原則一層へ置く。他の層は既知の言葉と慣れた因果で支える。新しい操作文法を採るなら物語と資源則を単純にし、変わった世界設定を採るなら操作と勝敗を即読可能にする。

固定コマンド自体が初見プレイヤーにとって新しい可能性もある。作者がリポジトリの標準操作に慣れていることを、プレイヤーの既知知識とみなさない。

### 認知負荷の収支表

| 覚える必要がある新要素 | いつ教えるか | 何回使うか | そこから生まれる異なる判断 | 既知の言葉で代替できるか | 判定 |
|---|---|---:|---|---|---|

次を不合格とする。

- 三つ以上の新用語・新規則を開幕でまとめて覚えさせる。
- 長い説明を読ませた規則が、一度の指定操作にしか使われない。
- 一つの特殊規則を覚えた後、対象名だけ変えて同じ操作を繰り返す。
- 説明量は増えるが、比較候補、リスク、結果の種類が増えない。
- 「斬新だから」を理由に、普通の扉・水・敵へ独自名と例外則を足す。

### 教える順序

新しい中心規則は、短い実演で教え、すぐ一度使わせ、その後に条件を変えて応用させる。

```text
見るだけで分かる実演
→ 一つの判断で成功する練習
→ 判断基準を一つ変えた変奏
→ 既知要素を二つまとめる山場
```

説明を読んだ時点で理解したことにしない。操作結果から規則を確かめられること。練習後の局面が同じ答えの反復なら、変奏ではなく水増しである。

### 負荷対効果

一つの新要素は、少なくとも二つの異なる判断または一つの大きな戦略判断へ効かせる。効かせられないなら、普通の言葉・既存規則へ戻す。企画全体が「認知負荷は高い／判断の種類は少ない」象限に入る場合は、設定説明を磨かず企画を作り直す。

## 9. 難易度とボリュームの校正

難易度は作者の意図でなく、解を知らないプレイヤーの行動で決める。

### 易しい

- 一つの観察から次の操作をほぼ一意に選べる。
- 多くの局面を初回の試行で通過できる。
- 資源判断はあるが、明白な安全策を選べば余裕がある。

### 普通

- 複数の観察を組み合わせる局面、または複数のもっともらしい配分を比べる局面が複数ある。
- 初見では安全な誤りや迷いが起こるが、結果から立て直せる。
- 目的欄や選択肢が正しい動詞・対象・順序を完成文で渡さない。
- 正解を知れば短くなるが、初見では観察と判断の時間が実際に生じる。

### 難しい

- 複数区間の情報統合、法則生成、長期資源計画等を要求する。
- 難語、隠し前提、総当たり量で難しさを偽らない。

設計時の難易度・尺は必ず「目標」と表記する。完成後は、解法を見ていないコールドプレイで次を測る。

- クリア時間（ツール待ち時間を除く）
- 各局面の試行数と迷った理由
- 観察せず正解できた局面数
- 同じ判断の反復と感じた箇所
- 回復・装備・経路で比較した候補

大半の局面が一観察・一発正解なら、作者がNormalを狙っていても完成ラベルはEasyに下げる。希望ラベルを守るなら局面を水増しせず、判断を作り直して再測定する。

尺は本文量や選択肢数でなく、初見の実測で決める。自動テスト、解法既知の最短経路、エージェント呼び出し待ちをプレイ時間へ混ぜない。未計測なら「推定」と明記する。

## 10. 企画判定

次がすべてPASSの案だけを詳細設計へ進める。

| 観点 | PASS条件 |
|---|---|
| 30秒ピッチ | 固有語なしのゲーム文と物語文で伝わる |
| ゲーム核 | 物語を外しても判断と上達差がある |
| 主体性 | 指示消化でなく、観察から手段を決める |
| 局面差 | 同じ認知操作による水増しがない |
| 既存差分 | 近い作品と中核5軸の3軸以上が異なる |
| 物語負債 | 開幕理解に複数の未知語や設定講義が要らない |
| 認知負荷収支 | 新要素が異なる判断を生み、単調な反復の説明費になっていない |
| 難易度 | 目標ラベルを支える局面設計がある |
| ボリューム | 意味のある局面表と実測計画がある |

一つでもFAILなら `NOT READY`。文章の整合、資源式、到達性が正しくても相殺しない。
