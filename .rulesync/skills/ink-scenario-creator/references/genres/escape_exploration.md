# ジャンルパック：脱出・探索

> SKILL.md §0 で構造タイプ＝**脱出・探索**（脱出ゲーム／ダンジョン探索／遺跡踏破 等）を選んだときに読むパック。
> 共通の作り方（状態秘匿・実装・検証）は SKILL.md と共通リファレンスに従う。

実装前に [escape_exploration_gimmicks.md](../escape_exploration_gimmicks.md) を必ず読む。六動詞の階層、脱出設計票、ボリューム下限、Ink例、回復可能性、公開境界は同書を正規の詳細契約とする。

## このジャンルの骨格

「閉じた空間／未知の領域を、**観察→道具と知識の組み合わせ→仕掛けの解除**で踏破する」過程を作る。核心は「正解を選ぶ」ことでなく、世界をいじって手応えを得る探索そのもの（[puzzle_design.md](../puzzle_design.md) §0）。

操作設計の原則は、**意味と組み合わせは隠すが、操作できる境界は隠さない**こと。未提示の名詞を当てさせず、正当な観察を経た必須対象は必ず Ink の選択肢へ出す。

## 固定六動詞

```text
しらべる → 見えている場所・物 → 発見済みの部位
とる → 露出している物
つかう → 所持品 → 発見済みの対象
おす・うごかす → 発見済みの可動部・操作部
もちもの → 所持品と既に観察した事実の確認
ばしょいどう → 部屋・安定した視点
```

毎画面に六動詞を全部表示する必要はない。物理的に対象がない動詞は非表示でよいが、新しいトップレベル解決動詞へ置き換えない。

発見は次の三段階にする。

1. 場面本文に最初から見えるランドマークを書く。
2. `しらべる → ランドマーク` で部位や周囲を発見する。
3. `しらべる → ランドマーク → 部位` で隠れた物や操作部を露出させる。

## 視覚操作から Ink への変換

| 視覚的な操作 | Ink の経路 |
|---|---|
| 視点・画面の切り替え | `ばしょいどう → 部屋・安定した視点` |
| 物へのズーム | `しらべる → ランドマーク` |
| 狭い隙間、裏側、細部のクリック | `しらべる → ランドマーク → 発見済みの部位` |
| ホットスポットのクリック | 対象の性質に応じて `しらべる`／`とる`／`おす・うごかす` |
| 所持品のドラッグ | `つかう → 所持品 → 発見済みの対象` |
| レバーや可動部のドラッグ | `おす・うごかす → 操作部` |
| ダイヤル・端末への入力 | `おす・うごかす → 入力装置 → 値を入力する` の先で `# input:` |

座標やピクセル位置は再現しない。プレイヤーが考えるのは、見えている対象の意味と組み合わせであり、作者だけが知るクリック位置ではない。

## プロット雛形（§1）

- 空間の全体像（区画／部屋／階層）と、**最終ゴール**（脱出・最奥到達・封印解除）
- 各区画の〈場所・目的・**封鎖（ゲート）**・あらすじ〉。ゲートは鍵／道具／知識／順序で開く
- 区画間の依存関係（A の発見が B の仕掛けを解く）＝**核心の仕掛け**

## 人物・環境の雛形（§1）

NPC は少数で、主役は**環境**。主人公の「できること／できないこと」（持てる物・届く範囲・知識）が解法の上限を縛る。NPC を置くなら、ヒント源／妨害／取引相手などの機能で。

## 中心メカニク語彙（§1.2）

**観察／アイテム発見・組み合わせ／仕掛けの操作／非自明な順序／封鎖の段階解除**。解は「宣言」でなく**世界への働きかけで実演**（[puzzle_design.md](../puzzle_design.md) の創発パズル・状態解錠）。

## 実装前の依存表

脱出設計票の一部として、本文や Ink より先に最低限次を埋める。完全な書式と規模別の数値は [escape_exploration_gimmicks.md](../escape_exploration_gimmicks.md#7-脱出設計票) を使う。

| 場所・視点 | 最初から見える物 | 調査後に発見される部位 | 必要状態 | 前提前の結果 | 前提後の結果 |
|---|---|---|---|---|---|

加えて、探索面マップ、依存グラフ、アイテム役割表、手がかりと錠の表、意味のある手数見積りを作る。`longform-scenario-review` の **Escape Exploration設計プレフライト**で `READY` になるまで Ink 実装へ進まない。

## ボリュームの伸ばし方（§1.5）

「区画数」や置物を増やすより、**依存の深さと発見フェーズ**を増やす。

```text
観察
→ 道具または事実を得る
→ 別の場所で操作する
→ 古い場所に新しい部位や意味が生まれる
→ 複数の探索線が統合する
```

難しくするなら、ミスリードの道具、行き止まりからの挽回、複数手順の合成を足す。ただし誤使用や誤順序で必須品を失わせない。

小／中／大の数値は置物の水増し目標ではなく、薄さを検知する下限として使う。手数には新規観察、状態変化、取得・使用、推論を試す操作、再文脈化された移動を数え、メニューの出入り、同文反復、無意味な往復は数えない。

## 禁止事項

- 未提示の対象名を自由入力させる名詞当て
- 最初から全対象を並べた巨大な一覧
- 知識フラグ後にだけ現れる「仕掛けを解く」「正しい順で押す」等の解法文
- 正解値、正しい道具、正解順序を本文・選択肢・入力要求に書くこと
- 外部 Web の可変情報、`RANDOM()`、shuffle、GM側の独自状態を進行条件にすること
- 誤使用、誤順序、誤入力で必須品を不可逆に消費すること
- 移動・再調査・再試行を once-only にして消すこと
- 同じ key-lock、同じ「何もない」、同じ往復による偽ボリューム

## 注意（必読）

- ソフトロック厳禁：取り返しのつかない消費／一方通行で詰む配線を作らない（SKILL.md §5 で検証）。
- 移動・再調査・再試行の選択肢は sticky（`+`）に。一度きり取得だけ `*`（[adventure_mcp_patterns.md](../adventure_mcp_patterns.md) の落とし穴 4）。
- 正解前後で同じ `つかう`／`おす・うごかす` 経路を保ち、返る結果だけを変える。
- 失敗は「不正解」ではなく、届かない、形が合わない、まだ動かない等の物理反応で返す。
- `public_status` は原則 `place` のみ。所持品と既知の事実は `もちもの` の authored text で確認する。
- 論理パズルを入れたら唯一解を機械検証（SKILL.md §4）。
