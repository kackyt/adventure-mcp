# RPGプレイヤー契約と使命設計

サバイバル・RPGでは、資源経済や戦闘を設計する前に、プレイヤーが「誰として、なぜ危険を冒し、何を達成するのか」を固定する。事件や世界の危機が存在するだけでは、主人公が行動する理由にならない。

## 1. 実装前ハードゲート

RPG設計票を作り、`longform-scenario-review` の **RPG設計プレフライト**で `READY` を得るまで、プロットの詳細化とInk実装へ進まない。

```text
RPG設計票を生成
→ RPG設計プレフライト
→ Blocker / Majorがあれば指摘を反映して再生成
→ 最大3回でREADYにならなければ実装せず停止
→ READY後にのみプロット・数値・Inkを実装
→ 完成後に同スキルでInk完成品を再レビュー
```

おまかせモードでも省略しない。ユーザーの追加回答がない場合はAIが具体案を確定するが、同じ設計を自己採点して通過させない。

## 2. プレイヤー開始契約

次をすべて具体的に書く。

| 項目 | 必須内容 |
|---|---|
| 主人公 | 名前または識別可能な呼称、社会的立場、現在の仕事 |
| 事件前の欲求 | 事件がなくても本人が求めていた具体的なもの |
| 来訪経緯 | なぜ今この場所にいるか |
| 最初の任務 | 動詞＋対象で説明できる作業 |
| 成功条件 | 世界内で観測できる完了状態 |
| 個人的利害 | 成功・失敗で主人公自身が得る／失うもの |
| 当事者性 | なぜ他の誰でもなく、この主人公が担当するか |
| 緊急性 | なぜ今すぐ行動する必要があるか |
| 継続理由 | 危険を知っても帰還・放棄しない合理的理由 |
| 完了確認 | プレイヤーが任務完了を判断できる結果 |

「村を救う」「世界を救う」は任務であり、動機ではない。なぜ主人公が救うのかを別に書く。

次だけでは不合格とする。

- ただの「旅人」「冒険者」
- 「善人だから」「困っている人を見捨てられない」
- 「運命に導かれた」「なぜか気になった」
- 報酬額だけがあり、誰との契約で何をすれば受け取れるか不明
- 記憶を取り戻したいが、事件との因果や達成条件がない
- 世界の危機だけを説明し、主人公個人の利害がない

最初の意味あるゲーム内選択までに、本文から「誰・欲求・来訪理由・当面の任務・完了条件」が読めるようにする。背景を長く講義する必要はないが、必要情報を謎として隠さない。

## 3. 使命の段階

主人公の行動理由を一本の因果列にする。

```text
事件前の欲求
→ 開幕の任務
→ 事件による当事者化
→ 観測した事実による目的更新
→ 最終決戦前に引き受ける使命
→ 固定コマンドで使命を実演
→ 達成／失敗としての結末
```

各矢印について「前段の何を観測したため、次を望むのか」を書く。NPCが次の場所を指定するだけでは、主人公の目的更新にならない。

最終選択肢で初めて、使命、代償、代替解法、世界法則を提示しない。ボスや最終関門へ入る前に、プレイヤーが「何のために戦うか」を説明できなければならない。

使命が途中で変わらない王道RPGも許容する。その場合も、開幕の任務が最後まで主人公の利害と接続していることを示す。

## 4. 作品の約束

次の形式で一文にする。

> プレイヤーは〈何を読み、判断し、操作し〉、〈何が足りなくなる緊張〉の中で、〈どの具体的目標〉を達成するゲームか。

例：

> プレイヤーは敵の予兆と坑道の地形を読み、装備と薬草の使用先を判断し、HPが最後まで足りるかという緊張の中で、星髄を採取して生還するゲーム。

次は作品の約束にならない。

- 壮大な物語を体験する
- 仲間との絆を深める
- 世界の真実を知る
- 選択によって運命を変える

抽象語を使う場合は、対応する操作・資源・完了状態を併記する。

## 5. 三つの反証テスト

設計者の説明で正当化せず、反証質問へ答える。

### 主人公置換テスト

> 主人公を「通りすがりの強い冒険者」へ置き換えても、同じ任務・情報・葛藤・結末が成立するか。

成立するなら、主人公固有の背景や能力が飾りである。主人公を簡潔な固定人物へ絞るか、固有要素をゲームへ配線する。

### 動機削除テスト

> 報酬、名声、家族、記憶、責任等の動機を削除しても、主人公は同じ場所へ行き、同じ危険を冒すか。

同じなら動機は差分テキストであり、因果ではない。

### 帰還可能性テスト

> 主人公が危険を知った時点で、任務を放棄して帰る方が合理的ではないか。

帰る方が合理的なら、契約、閉鎖、生存、時間制限、個人的損失、自ら引き受けた使命等を設計する。単にNPCが「お願い」と言うだけでは不足する。

## 6. 偽の職業・出自・動機選択を作らない

職業、出自、動機等をプレイヤーへ選ばせる場合、各候補が次のうち **二つ以上**を実際に変える。

- 利用できる情報
- 固定コマンドの対象・組み合わせ
- 攻略経路
- 支払う資源と損耗時刻表
- 装備・成長
- NPCとの社会的立場
- 中間目標
- 最終的な利害
- エンディングの意味

各障害へ「剣士なら力の成功文、斥候なら敏捷の成功文、学者なら知識の成功文」を並べ、全職が無傷で同じ場所へ戻る構造は偽選択である。選択を深く実装できない場合は、主人公を固定する。文章差分のためだけにキャラクター作成を置かない。

## 7. 関係は行動で獲得する

主要NPCごとに次を設計する。

- 初対面時の関係と相互認識
- 主人公が協力する実利的理由
- NPCが主人公を実際に助ける場面
- 主人公がNPCを実際に助ける場面
- 関係が変わる観測可能な出来事
- 相手へ好意を持たなくても任務を遂行できる経路

見知らぬ同行者を、登場直後から大切な人物として扱わせない。先に共同作業、危機の救援、能力の相互補完を置く。

`trust`、好感度、善悪度を使う場合も、作者が好む台詞への採点にしない。観測可能な約束の履行、救援、裏切り等を記録する。未説明の関係値を真EDの追加条件にしない。

## 8. 主題を操作と結果へ配線する

主題は登場人物の講義や哲学的回答のN択ではなく、プレイヤーの経験として設計する。

| 主題 | プレイヤーが観測する事実 | プレイヤーが行う操作 | 結果として理解できること |
|---|---|---|---|
| 例：準備は勇気に勝る | 無策の攻撃は大損耗する | 観察し、適切な装備を使う | 情報と段取りが生存を作る |

完成済みの思想文を複数並べ、作者推奨回答へ内部点を与えない。価値判断のN択を置く場合は、どれを選んでも異なる実在の利害と結果を持たせ、正解ED／格落ちEDの採点にしない。

## 9. 資源消費を任務進行へ接続する

既存の資源台帳に、消費の目的を加える。

| 資源消費 | 何を達成するための支払いか | 無料の代替手段 | 判断として成立するか |
|---|---|---|---|

次を不合格とする。

- ノーミス必須通行料が開始主資源以下
- 全障害を無料の職業専用回答で回避できる
- 回復材を使わなくても最終目標を達成できる
- 強力な消耗品より無料回答の方が常に優れる
- 任務進行と無関係な被ダメージを雰囲気だけで置く

詳細な数式、供給、時刻表は [survival_rpg_gimmicks.md](./survival_rpg_gimmicks.md) と [genres/survival_rpg.md](./genres/survival_rpg.md) に従う。

```markdown

- 一文契約:

- 主資源:
- 具体的な成功プレイ:

## プレイヤー開始契約
- 主人公の名前／呼称:
- 社会的立場・職業:
- 事件前からの具体的欲求:
- 来訪経緯:
- 最初の任務:
- 成功条件:
- 失敗時に主人公自身が失うもの:
- なぜ今か:
- なぜこの主人公か:
- 危険を知っても帰らない理由:
- プレイヤーが完了を確認できる状態:

## 使命の因果列
| 段階 | 主人公の目的 | その時点までに観測した事実 | 次へ進む理由 |
|---|---|---|---|
| 事件前 | | | |
| 開幕任務 | | | |
| 当事者化 | | | |
| 目的更新 | | | |
| 最終使命 | | | |
| 決戦での実演 | | | |
| 結末 | | | |

## 反証テスト
- 主人公を通りすがりの冒険者へ置換すると何が壊れるか:
- 動機を削除すると、なぜ同じ行動を取れなくなるか:
- 危険を知った後に帰らない方が合理的な理由:

## 選択の実効性
| 選択軸 | 候補 | 変わる情報 | 変わる経路 | 変わる資源 | 変わる利害・結末 | 二項目以上か |

```
