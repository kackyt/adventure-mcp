# 脱出・探索ギミック設計

脱出・探索では、画面上の座標を当てる代わりに、**見えている場所を選び、発見した部位へ段階的に近づく Ink の選択肢階層**を使う。

原則は次の一文にまとめられる。

> 意味と組み合わせは隠すが、操作できる境界は隠さない。

未提示の名詞を自由入力させず、正当な観察を経た必須対象は必ず選択肢へ出す。正解を知った後にだけ完成済みの解決コマンドを出すのではなく、同じ操作経路の結果を内部状態で変える。

## 1. 固定六動詞と階層

固定するのは、毎画面に六動詞をすべて表示することではなく、**使う動詞語彙と対象へ進む階層**である。物理的に対象がない動詞は非表示でよい。

```text
しらべる → 見えている場所・物 → 発見済みの部位
とる → 露出している物
つかう → 所持品 → 発見済みの対象
おす・うごかす → 発見済みの可動部・操作部
もちもの → 所持品と既に観察した事実の確認
ばしょいどう → 部屋・安定した視点
```

### 1.1 三段階の発見

1. 場面本文で、最初から見えるランドマークを示す。
2. `しらべる → ランドマーク` で、部位や周囲を選択肢として発見する。
3. `しらべる → ランドマーク → 部位` で、隠れた物、継ぎ目、穴、留め具などを物理的に露出させる。

`さがす`、`見つける`、`仕掛けを解く`のような新しいトップレベル動詞は増やさない。観察によって対象の存在へ気づき、その対象が以後のメニューに現れることは、解法の答え漏れではなく発見である。

### 1.2 名詞当てを作らない

- 未提示の対象名をプレイヤーに言い当てさせない。
- 必須対象は、正当な観察を通れば Ink の選択肢へ必ず現れる。
- 場面の全対象を最初から巨大な一覧にせず、ランドマークから部位へ段階化する。
- 同義語解釈は GM の入力補助にだけ使う。実行時は毎段階の正確な選択肢ラベルを `expectedText` へ渡す。

### 1.3 入力装置

暗証番号、文字列、ダイヤル値は自由入力できるが、入力装置へ到達するまでは固定六動詞で進める。

```text
しらべる → 入力装置
おす・うごかす → 入力装置 → 番号を入力する
```

カードや鍵で装置を有効化する工程は、別に `つかう → 道具 → 入力装置` で表す。入力待ちへ入る前に桁数や使える文字種を本文で示し、正解値や解法は本文、選択肢、入力要求へ書かない。誤入力は Ink が判定し、同じ経路から再試行できるようにする。実装契約は [adventure_mcp_patterns.md の自由入力モード](./adventure_mcp_patterns.md#自由入力モード-input-var完全一致の解答提出) に従う。

## 2. 視覚操作から Ink への変換

| 視覚的な操作 | Ink の経路 | 設計上の扱い |
|---|---|---|
| 部屋を見回す | 場面本文＋`しらべる → ランドマーク` | 最初から見える操作境界を本文に出す |
| 画面を切り替える | `ばしょいどう → 安定した視点` | 部屋、壁面、机の前など、往復する価値がある視点に限る |
| 物へズームする | `しらべる → ランドマーク` | ズーム後に部位や周囲を選べるようにする |
| 狭い隙間や裏側をクリックする | `しらべる → ランドマーク → 発見済みの部位` | 親を調べる前から隠し部位を出さない |
| ホットスポットをクリックする | `しらべる`、`とる`、`おす・うごかす` の該当対象 | 物理的な性質に合う動詞へ分ける |
| 物を拾う | `とる → 露出している物` | 取得だけ once-only。露出前は出さない |
| 所持品をドラッグして重ねる | `つかう → 所持品 → 発見済みの対象` | 正しい対象も誤使用先も同じ階層に置く |
| レバーや可動部をドラッグする | `おす・うごかす → 可動部` | 段階や向きは内部状態で管理する |
| ダイヤルを回す | `おす・うごかす → ダイヤル → 値を合わせる` | 必要ならその先で `# input:` を使う |
| 道具同士を組み合わせる | `つかう → 一方の道具 → もう一方の道具` | 組み合わせ後の所持状態を Ink で更新する |
| インベントリを見る | `もちもの` | 所持品と既知の観察事実を authored text で返す |

座標やピクセル位置を再現しない。プレイヤーが迷うべきなのは、**見えている対象をどう解釈し、何と組み合わせるか**であり、作者だけが知るクリック位置ではない。

## 3. 最小 Ink パターン

以下は構造だけを示す一般例であり、完成した謎の解法ではない。選択肢の入れ子は同じノットへ直書きせず、独立したノットへ分ける。

### 3.1 発見状態

```ink
VAR place = "作業室"
VAR public_status = "place"
VAR saw_fixture = false
VAR found_seam = false

=== room ===
壁際には大きな設備がある。
+ [しらべる] -> examine
+ [ばしょいどう] -> move

=== examine ===
+ [壁際の設備]
    ~ saw_fixture = true
    表面と側面を近くから見られる。
    -> fixture_parts
+ [戻る] -> room

=== fixture_parts ===
+ [表面]
    表面には細かな擦れがある。
    -> fixture_parts
+ {saw_fixture} [側面]
    ~ found_seam = true
    側面に細い継ぎ目が見つかった。
    -> fixture_parts
+ {found_seam} [継ぎ目]
    継ぎ目の奥に、別の部品がある。
    -> fixture_parts
+ [戻る] -> room
```

発見フラグは対象を物理的に認識したことを表す。`found_seam` を得た直後に「継ぎ目を正しい道具で開く」のような完成済み解決文を出さない。

### 3.2 内部所持品 `LIST`

```ink
LIST Item = flat_piece, cord, small_hook
VAR inventory = ()

=== function carries(item) ===
~ return inventory ? item

=== take_menu ===
* {found_seam && not carries(flat_piece)} [薄い部品]
    ~ inventory += flat_piece
    薄い部品を取った。
    -> room
+ [戻る] -> room

=== inventory_menu ===
{carries(flat_piece): 薄い部品を持っている。}
{carries(cord): 細いひもを持っている。}
{carries(small_hook): 小さな留め具を持っている。}
{not carries(flat_piece) && not carries(cord) && not carries(small_hook): 手元に使えそうな物はない。}
既に見た事実も、必要ならここで短く確認できる。
+ [戻る] -> room
```

脱出・探索では原則として `public_status = "place"` だけを公開し、`inventory`、発見フラグ、正解値、操作段階は公開しない。所持品と既知の事実は `もちもの` 配下の authored text で確認させる。

### 3.3 段階解錠

```ink
LIST GateStage = shut, released, open
VAR gate_stage = shut

=== operate_latch ===
{
- gate_stage == shut:
    留め具は固く、今は途中までしか動かない。
- gate_stage == released:
    ~ gate_stage = open
    同じ留め具が最後まで動き、通路が開いた。
- else:
    通路はすでに開いている。
}
-> room
```

前提がそろう前後で、`おす・うごかす → 留め具` という同じ経路を保つ。知識フラグ取得後にだけ「通路を開く」を出してはならない。

### 3.4 順序操作

```ink
LIST SequenceStage = start, first, second, complete
VAR sequence_stage = start

=== press_part_a ===
{sequence_stage == start:
    ~ sequence_stage = first
    小さな音が一度だけ返る。
- else:
    ~ sequence_stage = start
    音が途切れ、部品は元の位置へ戻った。
}
-> controls

=== press_part_b ===
{sequence_stage == first:
    ~ sequence_stage = second
    先ほどとは違う手応えが続く。
- else:
    ~ sequence_stage = start
    手応えが消え、最初から試せる状態に戻った。
}
-> controls

=== press_part_c ===
{sequence_stage == second:
    ~ sequence_stage = complete
    内部で機構がつながる音がした。
- else:
    ~ sequence_stage = start
    部品が戻り、最初から試せる。
}
-> controls
```

各候補は最初から同じ `おす・うごかす → 操作部` 配下に置く。正解順序を選択肢本文へ書かない。誤順序では必須品を失わせず、状態が戻ったことを物理反応で伝える。候補が複数ある順序仕掛けは、意図した順序だけが進行することを機械検証する。

### 3.5 誤使用からの復帰

```ink
=== use_flat_piece_on_slot ===
{not carries(flat_piece):
    手元に使える物がない。
- gate_stage == shut:
    幅は合うが、奥まで届かない。別の準備が要るようだ。
- else:
    部品が溝に収まり、機構が動いた。
}
-> room
```

失敗は「不正解」「決め手ではない」ではなく、届かない、形が合わない、まだ動かない、部品が足りない、という世界内の反応で返す。誤使用、誤順序、誤入力で必須品を不可逆に消費しない。

## 4. sticky と once-only

### sticky `+`

原則として何度でも必要になる行動に使う。

- 場所・安定した視点への移動
- 観察と再調査
- `もちもの`
- 道具使用と誤使用
- 可動部の操作
- 誤入力後の再試行
- メニューの「戻る」

### once-only `*`

世界内で本当に一度しか成立しない行動に限る。

- 露出済みの物を取得する
- 取り返せる必要がない一度きりの回収
- 明示された破壊や消費

普通の調査を `*` にして消すと、手がかりの再確認や GM の履歴確認ができなくなる。取得後は対象を消すだけでなく、親の再調査時に「跡だけが残っている」など状態に合う描写を返す。

## 5. outcome-gating

### 良い例

| 操作経路 | 前提前 | 前提後 |
|---|---|---|
| `つかう → 道具 → 対象` | 形は合うが固定されない | 同じ道具が収まり、対象が変化する |
| `おす・うごかす → 操作部` | 途中まで動いて止まる | 同じ操作部が最後まで動く |
| `しらべる → ランドマーク → 部位` | 表面の事実だけ分かる | 環境変化後に新しい痕跡が読める |

- 自然な操作経路が前提前から存在する。
- 失敗理由が世界内で分かる。
- 前提後も同じ経路を使い、結果だけが変わる。

### 悪い例

```ink
+ {knows_solution} [正しい順で操作して仕掛けを解く] -> solved
```

次も不適合である。

- 知識フラグ後にだけ「秘密の機構を開く」が現れる。
- 選択肢が正しい道具、対象、順序を完成文で説明する。
- 正しいコマンドだけが新しく現れ、出現自体が答えになる。
- 誤操作を GM の採点文だけで終わらせる。

## 6. 再調査、失敗、ソフトロック

### 6.1 調査済み領域の再描写

再調査は同文反復にしない。状態に応じ、少なくとも次のいずれかを返す。

- まだ調べていない部位が分かる。
- 取得済みの跡が見える。
- 環境変化後の新しい差分が見える。
- 既に調べ尽くしたことが分かる。
- 重要な事実を短く再確認できる。

同じ操作を複数回必要とする場合は、毎回の状態変化を本文で示す。同じ文章を必要回数だけ繰り返させない。

### 6.2 診断できる失敗

失敗時は、次の試行を狭める情報を世界内で返す。

- 届かない
- 大きさや形が合わない
- 固定されていない
- 動くが途中で止まる
- 何か一部が足りない
- 反応したが順序が崩れた
- 入力形式は合うが受理されない

正解を直接教える必要はない。プレイヤーが「操作対象を見落とした」のか「組み合わせを誤った」のかを区別できるだけの反応を返す。

### 6.3 ソフトロック防止

- 必須品を誤使用で失わない。
- 必須情報を一度きりの本文だけに置かない。`もちもの`、再調査、記録などで再確認可能にする。
- 誤順序は初期または診断可能な中間状態へ戻す。
- 誤入力後も同じ装置へ戻れるようにする。
- 移動、再調査、戻る選択肢を sticky にする。
- 各到達状態で、意味ある選択肢か明示的な終端を必ず残す。
- `RANDOM()`、shuffle、外部 Web の可変情報、GM 側の独自状態を進行条件に使わない。

## 8. ボリューム下限

| 規模 | 目標尺 | 発見フェーズ | 安定視点 | 主要ゲート | 意味のある操作 | 追加条件 |
|---|---:|---:|---:|---:|---:|---|
| 小 | 10〜15分 | 2以上 | 3以上 | 2〜3 | 20手以上 | 単純な鍵→扉だけで終わらせない |
| 中 | 25〜45分 | 3以上 | 5以上 | 4〜6 | 40手以上 | ランドマーク14以上、二段目の部位8以上、所持品6〜10個、同時所持4個以上、再訪2回以上 |
| 大 | 60分以上 | 4以上 | 8以上 | 7以上 | 70手以上 | 共作モード必須 |

数値は難易度ではなく、探索の薄さを検知する既定の下限である。コールドプレイで同等以上の厚みを示せる場合は、理由を設計票へ記録して調整できる。数を満たすための置物追加は不可。

### 8.1 意味のある操作に数える

- 新しい事実を得る観察
- 世界状態を変える操作
- 物の取得、使用、組み合わせ
- 手がかりから立てた推論を試す操作
- 新規視点への移動
- 後の発見によって意味が変わった視点への再訪

### 8.2 数えない

- メニューを開く、戻る
- 既知の同文反復
- 意味のない往復
- 尺稼ぎだけの定型失敗
- 正解既知の最短ルートにだけ存在する操作の重複

手数は、正解を知っている最短ルートではなく、手がかりを順に得る**想定初見ルート**で数える。

## 9. 偽ボリュームの検出

次は数が多くても薄い。

- 一巡で全対象と全所持品がそろう。
- `調べる → 鍵を取る → すぐ隣の扉へ使う`だけを繰り返す。
- 大半の置物が同じ「何もない」で終わる。
- 各所持品の用途が一対一で、取得時に使い先が一つしかない。
- 手がかりと入力装置が隣接し、その場で解ける。
- 同じ移動、同じ操作、同じ失敗文を反復させる。
- ランドマーク数を増やしただけで、発見フェーズ、統合点、再訪理由が増えていない。

短い場合は置物を足さず、発見フェーズ、依存の統合、場所をまたぐ再利用、サブ謎を増やして依存グラフから作り直す。

## 10. 公開境界

脱出・探索の既定は次のとおり。

```ink
VAR place = "現在の視点"
VAR public_status = "place"
```

公開するのは現在の場所・安定視点だけとする。所持品、発見状態、操作段階、解錠状態、正解値、ミスリードは公開しない。GM は `scene`、`choices`、`status.place` だけから状況を示し、所持品は `もちもの`、既知の事実は本文または authored text で確認する。
