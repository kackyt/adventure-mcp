## 0. ハーネス：どんな戦闘を発明しても守る不変則

戦闘・魔法・資源のメカニクスは**作品ごとに発明してよい**——むしろ毎回同じ形だと既視感になる（§10 のカタログと選択規律を使う）。ただし以下だけは、どんな発明でも守る。エンジン・機械検証・ジャンルの骨格が要求する「ハーネス」であり、各則には検証手段が対応する。**数値や個別メカニクスの処方はここには無い**——それらは §5 の式と §10 のカタログから毎回導出し直すもの。

### 0.1 プラットフォームの壁（交渉不可）

- **完全決定論**: 勝敗・詰みに関わる判定に `RANDOM()` やシャッフル出力 `{~a|b}` を使わない。同じ入力は同じ結果。テキストの揺らぎが欲しい場合もサイクル `{&a|b}` か訪問回数条件で書く。これがある限り、どんな奇抜な戦闘もスモークテストで機械検証できる。
- **固定コマンドパレット**: 新しい動詞を生やさない。奇抜さは しらべる／とる／たたく／つかう／うごく の**新しい組み合わせ**で出す（PUZZLE_DESIGN §6.3）。
- **公開最小主義**: 敵の内部状態・勝敗フラグ・存在が謎の鍵になる物は `public_status` に載せない（§1）。
- **敗北は終端 ED**: 主資源の枯渇は必ず終端 ED。ソフトロック禁止（§8）。

### 0.2 設計の不変則（メカニクスに依存しない本質）

1. **判断が宿る** — どの戦闘にも「情報を使う一手」がある。無い戦闘は通行料と割り切り、支払う額（被ダメ）が準備の質（装備・情報）で変わるようにする（§4）。
2. **勝利は資源を動かす** — 無償の勝利はフィラー。戦闘の結果は勝敗の二値でなく収支として残る（§5）。
3. **実力＝情報×段取り** — 乱数も反射神経もない世界では、強さの源泉は観察・順序・ルート・知識だけ。だから**戦闘の解は必ず世界のどこかに読み取り可能な形で書いてある**。入力の摩擦（長文の手打ち等）を壁にしない——壁は「世界を読んだか」にだけ置く。
4. **総当たりは破産する** — 盲目の反復は予兆つきコストで資源を燃やし、最適戦略にならない（ごり押しスモークで検証）。
5. **経済の不可侵** — 新メカニクス（装備・強化・魔法）が既存メカニクスの抑止経済をゼロにしない。軽減装備の「最低 1 は通す」はこの一実例にすぎない。
6. **管理の強制** — 主資源は、正解プレイでも配分判断なしには足りない量に設計する（§5.1）。主資源は HP と限らない——灯りの油・残り時間・体温など、作品ごとに発明してよい。
7. **単調性とフェアネス** — 賢いプレイが常に優位で、逆転しない（§5.4 の類型検算）。ルールは死ぬ前に世界内で学べる。

## 1. インベントリ：公開 LIST ＋ 内部フラグ LIST の分離

装備・キーアイテム・状態異常は Ink の `LIST` で持ち、**プレイヤーがキャラクターシートとして見えていて当然のものだけ**を `public_status` に載せる（INK_GUIDE §4.5 のプレイヤー可視原則）。存在自体がネタバレになる隠しアイテムや勝敗フラグは**別の LIST／変数に分離**して非公開にする。

```ink
// 公開してよい: プレイヤーが持ち物欄で見えていて当然のもの
LIST equipment = (rusty_dagger), miners_lamp, steel_pick
LIST conditions = poisoned, blessed
// 非公開: 存在自体が謎の鍵になるもの・進行フラグ
LIST secrets = moon_sigil
VAR boss_beaten = false

VAR player_hp = 20
VAR herb_count = 2
VAR public_status = "player_hp, herb_count, equipment, conditions"
```

- エンジンは LIST を **`", "` 区切りの文字列**（例 `"rusty_dagger, miners_lamp"`）に正規化して AI へ渡す。空 LIST は `""`。
- **消耗品の個数は LIST で持てない**（LIST は集合＝同じアイテムを2個入れられない）。薬草×3 のような在庫は `VAR herb_count = 3` の int カウンタで持つ。
- LIST のアイテム名は ink の識別子。**snake_case 英小文字**とする（漢字は通るが、ひらがな・カタカナはコンパイルエラー。日本語表記は GM の演出に委ねる）。
- 所持判定はヘルパ関数に切り出すと読みやすい:

```ink
=== function carries(item) ===
~ return equipment ? item
```

## 2. tunnel 戦闘の勝敗判定（落とし穴5の実装形）

tunnel（`-> combat ->`）は勝利でも逃走（`->->`）でも同じ場所へ戻るため、**戻り先では結果を判別できない**。勝利時のみ立てるフラグを win gather 内でセットし、呼び出し側で分岐する。

```ink
VAR last_battle_won = false

=== combat(foe, foe_hp, dmg) ===
~ last_battle_won = false
{foe}が立ちはだかった！
- (round)
{ player_hp <= 0: -> lose }
{ foe_hp <= 0: -> win }
+ [斬りかかる]
    ~ foe_hp = foe_hp - attack_power()
    ~ player_hp = player_hp - dmg
    -> round
+ {herb_count > 0} [薬草を使う（残り{herb_count}）]
    ~ herb_count = herb_count - 1
    ~ player_hp = player_hp + 8
    ~ player_hp = player_hp - dmg
    -> round
+ [逃げる]
    ->->
- (win)
{foe}を打ち倒した！
~ last_battle_won = true
->->
- (lose)
-> game_over

// 呼び出し側: 勝利と逃走を取り違えない
=== floor_3 ===
{ not gatekeeper_beaten:
    -> combat("門番", 16, 4) ->
    { last_battle_won:
        ~ gatekeeper_beaten = true
    - else:
        門番はまだ通路を塞いでいる。
    }
}
```

**NG**: 戦闘ノット末尾（tunnel 復帰直前）で一律に撃破フラグを立てる——逃げても撃破扱いになる。

## 3. 「初回だけ戦闘」は真偽フラグで（落とし穴1）

自己ループ（`-> floor_2` で同じ knot に戻る）では**訪問回数が増えない**（inkjs の既知の癖）。`{ floor_2 == 1: ... }` で初回戦闘を制御すると再訪のたびに再発する。上のテンプレのとおり**明示的な真偽フラグ**（`gatekeeper_beaten`）で管理する。

## 4. 前提ゲート型戦闘：必須装備なしでは数値上勝てない

「装備が無いと**与ダメージが 0**（または敵の防御を抜けない）」にすると、プレイヤーがどれだけ粘っても敵 HP が減らず、HP 収支で必ず敗北する——つまり**数値上勝てない**ことが機械検証できる。

```ink
=== function attack_power() ===
// 前提ゲート: 灯りが無いと闇に潜む敵に刃が届かない
{ not carries(miners_lamp):
    ~ return 0
}
{ carries(steel_pick):
    ~ return 8
}
~ return 4
```

- ゲートの**根拠は世界の理**として、より前の階層のヒントで示す（「門番は光を嫌う」等）。装備チェックだけが浮いていると理不尽になる。
- スモークプレイでは**「必須装備なしでは勝てない」「ありでは勝てる」を両方**検証する（SKILL.md §5）。

## 5. 資源経済の設計（レベルデザインの取りどころ）

決定論戦闘の RPG では、HP は強さのメーターではなく**道中ずっと燃える燃料**。ゲームバランスの醍醐味はこの資源経済にあり、数値は以下の原則から**導出**する（感覚で個別調整しない——場当たりの調整は何度でもやり直しになる）。

### 5.1 戦闘は本物の通行料（ノーミスでも回復材が要る）

装備ゲートが勝敗を決めても、**勝利は痛くする**（ざこ＝資源を削る、の原典どおり）。基準式:

```text
通行料 = 正解装備・ノーミスの必須戦闘の被ダメ合計
設計条件: 通行料 ＞ 開始HP
余剰マージン = (開始HP + 携行回復量 × 入手可能数) − (通行料 + 想定ミスの被ダメ)
```

- **通行料＞開始HP** にすると、携行回復を挟まずにはクリア不能＝「どこで回復を切るか」の配分判断が**全員に**発生する。通行料が開始HPを下回ると、上手いプレイヤーには回復が無用の長物になり、戦闘の重みが消える。
- 余剰マージンの目安は被弾2〜3回分。「ノーミスで回復材1本必須／供給全量で吸収できるミスは N 回／それ以上は死圏」と数値で言えるように逆算する。
- 調整ノブは3つ: **開始HP／敵ごとの被ダメ／回復量と入手数**。
- 主資源が HP でない作品（油・時間・体温 等）でも、同じ式を主資源で立てる。
- **具体の数値は毎回この式から導出し直す**。worked example（star_marrow: 通行料23＞HP20・薬草3本×6）は一つの解であって法則ではない——数値ごと写すと同じゲームができる。

### 5.2 資源には役割を1つずつ（重複させない）

| 資源 | 役割 |
| --- | --- |
| 携行回復（薬草等） | 生命線。どこで切るかの配分判断 |
| 据え置き（泉等） | **役割限定**の節目（解毒・状態回復など）。汎用回復にしない |
| 恒久軽減（防具等） | 以後の失敗の単価を下げる保険（§6.2 リスク購入で買わせる） |

役割が重複した瞬間に片方が不要になる（「携行回復が潤沢なら全快の泉は要らない」）。とくに**決戦直前の全快チェックポイントは禁止**——そこまでの収支と戦闘の重みを全部消してしまう。

### 5.3 供給は前積み

回復材は「必要になる直前」に配らない（just-in-time 配布は配分判断を殺す）。序盤〜中盤に前積みし、後半に向けてラショニング（配分）させる。

### 5.4 検算：プレイヤー類型別の時刻表（着手前と書き上げ後の両方）

階層×通行料×補給の時刻表を書き、**回復なし累積HPの赤線がどの階で 0 を割るか**を見る（終盤で割るのが正しい形）。そのうえで類型ごとに残HPを追い、**単調性**（賢いほど残HPが多く、雑なほど死に近い。逆転がない）を確認する:

| 類型 | 確認すること |
| --- | --- |
| ノーミス | 回復材の必須本数（1本以上になっているか） |
| 初見（ミス数回） | 供給全量で吸収できるミス回数 |
| ごり押し | 資源が尽きて敗北EDへ落ちる（中途半端に生還できない） |
| リスク購入（早買い・遅買い・安全買い） | どのタイミングにも生還線があり、支払いが空洞でない |

代表値（購入直後のHP・関門通過後のHP など）は**スモークテストに数値で焼き込む**。
無警告の回復ゼロ区間は作らない。ただしリスク購入の封印区間（§6.2）は事前警告＋自己選択なので例外。

## 6. リスク選択とリスク購入

### 6.1 リスク選択：どの資源で払うか

前進のコストを**複数の資源のどちらで払うか**選ばせる（例: 危険な近道＝HPで払う／回り道＝消耗品で払う）。どちらも前進できることが条件（選択肢の一方が実質死、は選択でなく罠）。

```ink
=== crossroad ===
崩れた坑道を抜ければすぐ先に出られるが、天井が今にも落ちそうだ。
迂回路は崩れる心配こそないが、長い。水と糧を食うだろう。
+ [崩れた坑道を駆け抜ける]
    落石があなたを掠めた。（HP -6）
    ~ player_hp = player_hp - 6
    { player_hp <= 0: -> game_over }
    -> next_floor
+ [迂回路をゆく]
    長い道のりに水と糧を使った。（薬草 -1）
    { herb_count > 0:
        ~ herb_count = herb_count - 1
    - else:
        // 支払い資源が尽きているときは別資源に振り替える（無料にしない）
        飲まず食わずの行軍が体にこたえた。（HP -2）
        ~ player_hp = player_hp - 2
        { player_hp <= 0: -> game_over }
    }
    -> next_floor
```

- **「時間」は、手数が主資源を削る仕組みのある作品でしか対価にならない**（例: 1歩ごとに灯りの油が減る・潮が満ちる）。時計のないコマンド入力型で「遅い」は誰のコストでもなく、無償の安全ルートは選択を消す（全員が安全側を選ぶだけになる）。
- **支払い資源が尽きているときの挙動を決めておく**（無料にしない——別資源に振り替えるか、その選択肢を塞ぐ）。
- 対価は**決定論の固定値**にする（確率で分けない）。
- 対価は両方とも事前に示唆する（後述の詰み線引き：**詰みに入るのは危険が事前示唆された選択の結果のみ**）。

### 6.2 リスク購入：恒久強化を代償で買わせる

防具・恒久バフのような「以後ずっと効く」強化は、タダで拾わせず**リスク購入**にする。設計の芯は4つ:

1. **支払いが先・回収が後**。支払いとその解消手段の間に**本物の区間（関門）**を置く。解消手段が購入場所の隣にあると支払いが空洞化し、「知っていれば取り得」の一方的選択になる（それは選択ではない）。
2. **支払いは現在状態に比例**させる（例: 現在HPの半減）。買うタイミング自体が賭けになり、「弱ってから買えば安いが、そこからの道中が綱渡り」というプレイングが生まれる。
3. **期待値はほぼ中立**に。価値の本体は分散の圧縮（＝以後の未知の失敗が安くなる保険）。ネットで明確に得な購入はただの正解であり、選択にならない。
4. **軽減は最低1を通す**（被ダメ −2 でも 0 にしない）。総当たり抑止の HP コスト経済を、装備で殺さない。

フェアネス: 支払いの**ルール**（回復封印・解消条件が存在すること等）は、購入前に現場で読めること。「しらべる」で警告（先人の失敗の痕跡など）を見るまで取得の選択肢自体を出さない、という導線で担保するとよい。
実装例: [star_marrow_mine.ink](../../../../engine/assets/star_marrow_mine.ink) の革のよろい——毒の霧の中のなきがら（かみかけの薬草＝「毒に薬草は効かない」の現場警告）、解毒は関門の先の泉のみ。

## 7. 階層設計表（着手前に必須）

ウィザードリィ型の階層ダンジョンでは、書き始める前に**階層ごとの配置表**を作ってバランスを取る。

| 階 | 敵 | 必須アイテム（入手→使用） | ヒント（入手→使用） | 回復・補給 |
| -- | -- | -- | -- | -- |
| B1 | ざこ（素手で勝てる） | 錆びた短剣（B1→B1以降） | 「門番は光を嫌う」（B1→B3） | 薬草×1 |
| B2 | なし（リスク選択） | 坑夫灯（B2→B3） | — | 薬草×1 |
| B3 | 中ボス＝前提ゲート（坑夫灯必須） | 鋼の鶴嘴（B3→B4岩盤・B5） | 「護符の理」（B3→B5） | — |
| B4 | なし（瘴気＝状態異常） | 欠月の護符（B4→B5） | — | 回復の泉 |
| B5 | ラスボス＝前提ゲート（鶴嘴＋護符必須） | — | — | — |

設計ルール:

- **ボリューム定義**: 小＝3階層くらい／中＝4〜10階層／大＝11階層以上。ボリュームは階層数で決め、各階の密度は保つ。
- **またぎ制約**: ヒント・必須アイテムの**取得階と使用階の階差は2まで**（B1→B3 は OK、B1→B4 は NG）。プレイヤーの記憶と再訪コストが破綻するため。いろんな階層にちりばめるのは推奨、遠くへ飛ばすのが禁止。
- **成長ガード**: 階層を進むと強い武器・装備が手に入り（成長体験）、**弱い状態では次の階層へ進めない関門**（岩盤を砕くには鶴嘴が要る等）を置く。関門は前提ゲート型戦闘でも、装備による通路の開通でもよい。
- **敵の配役**: ざこ（資源を削る）／中ボス（前提ゲート＋成長報酬）／ラスボス（全要素の収束）。暗号・パズルを置く場合も同じ表で管理する。
- **収支列を持たせる**: 表に「通行料（その階の必須被ダメ）」「回復なし累積HP」の列を足し、赤線が 0 を割る階（終盤にあること）と類型別の単調性を確認してから書き始める（§5.4 の時刻表検算）。

## 8. 詰みの線引きと敗北ED

- **敗北（HP 0）は必ず終端ED**にする（`-> END` / `-> DONE` で終わる game_over ノット）。選択肢ゼロで宙吊りにしない。
- **詰み（資源を使い果たして勝てない状態）は限定的に許容**するが、次を守る:
  - 詰みに入るのは**危険が事前示唆された選択の結果**のみ（無警告の不可逆消費で詰ませない）。
  - 詰み状態からも**必ず敗北EDへ到達できる**（ボスに挑んで敗れる等。逃げ続けるしかない無限徘徊で放置しない）。
- スモークプレイで「最悪プレイ（回復を全部無駄遣い・寄り道最大）でも ED に到達できる」ことを確認する（SKILL.md §5）。

## 9. スモークプレイの検証項目（このジャンルの追加分）

共通の検証（デッドエンド無し・クリア到達可・敗北は終端ED）に加えて:

- [ ] 前提ゲート戦闘: **必須装備なしでは勝てない**（粘っても敵HPが減らず敗北EDへ）
- [ ] 前提ゲート戦闘: **必須装備ありでは勝てる**
- [ ] 一度きり戦闘が**再訪で再発しない**（真偽フラグ管理）
- [ ] 逃走後に**撃破扱いになっていない**（勝敗フラグの取り違えなし）
- [ ] 最悪プレイ（回復の無駄遣い）でも敗北EDに到達できる（ソフトロックなし）
- [ ] `public_status` に勝敗フラグ・隠しアイテムが載っていない
- [ ] **通行料＞開始HP** を検算した（正規ルートのスモークプレイに回復材の使用手が入っている）
- [ ] 決戦直前に全快チェックポイントがない（据え置き回復は役割限定）
- [ ] リスク購入がある場合: 支払い→関門→解消の区間が実在し、代償ルールが購入前に現場で読める（警告を見るまで取得選択肢が出ない導線をテストで検証）
- [ ] 恒久軽減があっても予兆つき失敗コストが 0 にならない（最低1）
- [ ] 戦闘メカニクスを §10 の選択規律で選んだ（直近作品と同じ骨格の反復なし）
- [ ] 新メカニクス（魔法・巻物 等）が §10.2 の尋問 5 問に世界の中で答えている

vitest でのスモークテスト実装例: [star-marrow-mine.spec.ts](../../../../engine/src/smoke/star-marrow-mine.spec.ts)。

## 10. 戦闘メカニクスのカタログ（選択規律つき）

戦闘の形を outcome-gate 一本槍にしない。これは [code_lock_ideas.md](code_lock_ideas.md) と同じ「生成メニューでなく検証つきカタログ」——**§0 のハーネスを満たす限り発明は自由**で、以下は判断の所在とフェアネスが検証しやすい代表形。

### 選び方（必読——固定の好みで選ばない）

1. **題材・世界に必然として存在しうるか**（物語接地）で候補を絞る。
2. 複数が同等に合うなら**乱数で選ぶ**（毎回同じ形に寄せると作品をまたいだ既視感になる）:
   `node -e "const c=['C1','C3','C4']; console.log(c[Math.floor(Math.random()*c.length)])"`
3. **同一作品内・直近の作品で同じ骨格を反復しない**（star_marrow は C0＋リスク購入を使用済み）。
4. 骨格は作品固有の血肉で着せ替える。骨格が透けたら既視感。

| # | 名称 | 骨格 | 判断の所在 | フェアネス注意 |
| --- | --- | --- | --- | --- |
| C0 | outcome-gate（既定） | 正しい準備の有無で勝敗が決まる（§4） | 事前の鍛冶・入手・情報収集 | ゲートの根拠を世界の理で先出し |
| C1 | まきもの（一度きりの魔法アイテム） | 単発・強力・不可逆の消耗品で突破 | どこで切るかの配分 | §10.1 を必読 |
| C2 | 行動パターン読み | 敵は決定論の拍子で動き、しらべるで観察できる。正しい拍に打てば浅く、外すと深い | 観察→拍の特定 | パターンは必ず観察可能に。拍の答えを本文・選択肢に書かない |
| C3 | 環境キル | 敵は直接倒せず、地形（水・崩落・火気）へ誘導・作用して仕留める | 敵の習性×地形の因果 | 作用が効く条件を物理で限定する（万能鍵防止） |
| C4 | 回避経済 | 倒せない敵。戦わないこと自体にコスト（遠回り・資源・音） | どのコストで払うか | 回避側も必ず前進できる（一方が実質死の選択は罠） |
| C5 | 代償支払い | 勝利・通行の対価に装備や資源を差し出す | 何を手放すか | 手放した物が後で必須にならないこと。必須にするなら事前示唆＋敗北ED経路 |
| C6 | 命削りの詠唱 | 魔法の代償を現在HPから直接払う（MPを作らない） | 残量と効果の天秤 | とがった変種。回復魔法は原理的に成立しない（HPでHPを買う矛盾）＝役割重複が構造で防がれる |

### 10.1 まきもの（C1）の作法——無難で強い既定解

一度きりの消耗品は、ハーネスの大半を**構造で**満たす（弾＝それ自体／誤射＝永久喪失＝決定論で最も重い誤射コスト／どんなに強くても壊せる錠前は一つ＝配置数が設計者の完全な制御下）。残る設計判断は 2 つ:

- **役割の一意性**: 回復の巻物は作らない——名前と絵を変えた薬草にすぎず、役割が重複する（§5.2）。巻物の役割は**突破**に限る——前提ゲートの代替鍵・一点スキップ・ユーティリティ。攻撃資源と回復資源が別々に減ると、終盤の残弾計算が立体的になる。
- **謎解きの経済に触れさせない**: 謎の答え・解法を買える巻物を作らない。**答えを対価で買えた瞬間、その謎は死ぬ**（伏線の冗長化禁止と同じ構造）。巻物が破ってよいのは戦闘と障害物まで。

フェアネス: **効果は使う前に読めること**（「使ってみるまで不明」はランダム識別ゲーの流儀で、決定論の一度きり資源では理不尽）。特定ゲートの想定解にするなら取得階と使用階の階差 2 ルール（§7）に乗せる。「もったいなくて使えなかった」は失敗ではない——配分判断が機能している証拠。

### 10.2 「魔法を入れたい」の模擬尋問（ハーネスの使い方の実例）

「RPG だから魔法を」と思ったら、禁止ではなく次の 5 問に**世界の中で**答える:

1. **何の判断を足すのか？** 魔法の効果が「既存の攻撃（たたく）よりダメージが大きい」だけなら、武器の強化と同じで新しい判断を生まない＝入れる意味がない。入れてよいのは、**「どの魔法を・何に・いつ使うか」の正解が本文の観察から推論できる**とき（例: 「ぬれた毛皮」の描写→凍結が通ると推論できる／「水は凍ると膨張する」という世界の事実→溜まり水を凍らせて岩の裂け目を割る）。相性表の暗記（火は氷に強い等）＋ヒント一行は推論ではなく知識クイズなので、これを満たさない（後述の没例）。
2. **弾は何か？** 自然回復する無限 MP は不可（無償の勝利製造機＝§0.2-2 違反）。消耗品・回数制・HP 支払いなど、希少な何かで払う。
3. **回復魔法は携行回復の座を食わないか？** 役割の一意性（§5.2）で処理する。併存させるなら役割を分け、座を譲るなら元を廃する。
4. **万能鍵になっていないか？** 効く条件を限定する（一度きり・物理条件・対象限定）。どの壁も開く魔法はパズル経済を、全敵に通る魔法は前提ゲートを破壊する。
5. **誤射のコストと予兆は？** 「全部の敵に全部試す」総当たりが破産する構造か。

5 問に別々の答えを出せば、魔法のある作品同士でも別のゲームになる。**没例も記録しておく**: 詠唱を自由入力（`# input:`）でやる案は、入力が面倒な割にコピペで再利用できて壁にならず没——壁は「世界を読んだか」にだけ置く（§0.2-3）。属性相性表（火は氷に強い式の暗記）も判断でなく暗記なので避ける。

## 11. 謎解きとの結線（謎が骨、経済が血）

このジャンルでも中心は謎解きと探索——ここが痩せると「叩けるところを叩けばクリアできる」作業ゲーに落ちる。謎の作り方そのものは [puzzle_design.md](puzzle_design.md)（**認知操作×題材×提出経路**の因数分解＝§6.1、物語接地＝§6.2）に従う。本節は謎と RPG 経済の**結線**だけを定める。

1. **世界観への接地が絶対条件**: 謎はその階層世界の営み・物・理から導出する（鉱山なら排水・レール・鍛冶。世界と無関係に降ってわいたパズルは没）。戦闘・資源も同じ——毒も装備も敵も、その世界にある理由が立つこと。
2. **役割分担**: 前進の鍵＝謎（フロアゲートは原則、洞察で開く）。戦闘・資源＝試行の値段と成長のリズム。戦闘で謎の道は開かない。
3. **洞察は無料、試行は有料**: 考える・しらべるはコスト 0。資源を燃やすのは**まちがった行動**だけ（予兆つき・§0.2-4）。試行まで無料だと総当たりが最適戦略になり謎が死ぬ。洞察が無料だから、資源が尽きかけても正しい答えを持つ者は前進できる（§8 のソフトロック禁止と両立）。
4. **非対称ルール**: 資源で謎は買えない（答え・解法を売る巻物や NPC は禁止＝§10.1）。逆に**謎は資源を払ってよい**——脇道の任意の謎には薬草・装備・近道で報いる（探索の動機になる）。
5. **理の再演**: 序盤の謎で学んだ世界の理を、終盤の戦闘の仕掛けとして回収する（例: star_marrow——B2「水は行き場がないとあふれ返る」→ B6 ボスの二段排水）。謎の報酬が知識で、知識の換金先が決戦。取得と使用は階差 2 まで。
6. **戦闘そのものを謎に**: §10 の C2（行動パターン読み）・C3（環境キル）は戦闘の皮をかぶった謎。謎解きと RPG の境界が消えるのが理想形。
7. **リズム**: 階ごとに主役を交代させる（謎解き階／探索階／関門階／収束階）。全階で全部やると密度が死ぬ。逆に「謎パートの間だけ RPG が止まる」別ゲーの縫合も禁止——**誤答の試行と戦闘が同じ主資源のメーターを共有している**ことが、一つのゲームである条件。

検証: 各謎の認知操作が作品内で重複していないか（puzzle_design §6.1 の規律 2）、必須の謎が「解けないと進めない壁」であって「資源を食う穴」になっていないか（考え直しは何度でも無料）をスモークプレイで確認する。
